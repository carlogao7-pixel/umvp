## 组装工（assembler · plan 模式）
_ok=True steps=1 tools=[]_

若落地，我会：

1) **需求解析**：从总装工提供的需求链条中提取关键信息，包括场景（车间里检测有没有人抽烟）、目标（拍到就告警）。同时，我会根据需求链条中的问题，询问用户以下信息：
    - 检测范围：整个车间还是特定区域？
    - 告警方式：手机短信、语音播报等。
    - 检测精度：是否需要区分吸烟者是否在吸烟？
    - 环境因素：车间内是否存在烟雾、明火等干扰因素？

2) **选参数**：根据提取的需求信息，结合 `list_modules` 获取的模块参数信息，初步确定以下模块的参数：
    - **frame_manager**：设置合适的采样频率和帧率，确保能够覆盖整个车间或特定区域。
    - **yolo**：选择合适的模型和参数，以提高检测准确率。
    - **det_filter**：根据需求，可能需要设置过滤规则，以排除非吸烟者的干扰。
    - **seq_filter**：根据需求，可能需要设置节流或变化规则，以减少误报。
    - **target_crop**：根据需求，可能需要设置裁剪区域，以聚焦于特定区域。
    - **annotate**：设置标注参数，以便后续分析。
    - **vlm**：根据需求，可能需要设置合适的提示词和模型，以便实现告警功能。

3) **写 spec**：根据选定的模块和参数，按照 `07-shell-templates.md §2` 参数白名单，编写完整的 JSON 格式的 spec。

4) **自检**：使用 `validate_spec` 校验 spec 是否满足硬性规则和参数白名单，确保 spec 的有效性。

5) **估算**：使用 `estimate` 对 spec 进行资源估算，包括单链路和多路情况下的显存、内存和帧率等资源消耗。

6) **测试（可选）**：根据需要进行断言式测试或限帧真实推理烟测，以确保链路的功能和性能。

7) **汇报**：将方案、spec、校验结果、资源报告和测试结果（如有）整理成文档，提交给总装工。
