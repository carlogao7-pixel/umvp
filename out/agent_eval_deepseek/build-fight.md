## 设计说明（给组装工）

1. **为什么必须上 VLM**：打架是行为语义，YOLO 只能给"人"的框，判不出行为。所以链路是 **YOLO 定位人 → annotate 画框 → VLM 研判**。
2. **为什么用 annotate 而非 target_crop**：VLM 需要看**整帧场景**（两人相对位置、动作关系），裁剪单人子图会丢失"打架"的上下文。annotate 只喂 VLM，符合机制。
3. **det_filter 出现两次**：第 3 段是**同帧有效性筛选**（只留人、人数下限），第 7 段是**事件尾**（VLM 命中词表时标事件）。两处职责不同，符合"筛选 + 事件生成"机制。
4. **seq_filter 节流**：门口画面变化慢，节流可显著降低 VLM 调用量（VLM 是成本大头）。
5. **待组装工落地/待验证**：具体抽帧间隔、conf、节流秒数、VLM 提示词与词表、事件名与 detail 字段，均由组装工按模块参数表落值并校验。

需要我调整吗？比如：是否要**同时保留打架瞬间的截图**（事件带框/带图）、是否要**更灵敏**（宁可误报不漏报）还是**更稳**（少误报）——这两点会影响抽帧频率、VLM 提示词与事件尾的严格度。
