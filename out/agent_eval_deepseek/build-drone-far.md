## 一、需求整理复述

| 项 | 内容 |
|---|---|
| **对象** | 无人机高空俯拍画面中的**远处小目标**（人）与**车辆** |
| **场景** | 高空俯拍、目标在画面中占比很小、距离远 |
| **核心诉求** | **尽量不漏**（召回优先，宁可多报不可漏报） |
| **隐含约束** | 高空俯拍 → 目标小 → 默认推理分辨率会大量漏检；需在"看得清"和"算得动"之间取舍 |
| **待确认** | ① 输出形态：只要**检出/统计**，还是要**告警事件**（如"某区域出现车辆"）？② 是否要**出图**（画框/子图）？③ 路数、显存预算？④ 是否要 VLM 二次研判？ |

**关键判断**：这个需求的技术命门是 **YOLO 的推理分辨率（imgsz）**。决策表实测结论明确——远角小目标场景 **imgsz 1280 是"几乎免费"的召回提升**（GPU 下 1280 vs 640 耗时仅 +26ms/帧），640 下小目标 track 会全灭；同时 **conf 要放宽到 0.15** 才能找回远角目标（0.50 会直接丢目标）。这两点是"不漏"的主要杠杆。

**设计说明（业务层）**：
- 链条走**检测流**：抽帧 → 检测 → 同帧筛选 → 跨帧防抖，尾段 `seq_filter` 出事件，符合终段白名单。
- **"不漏"落在两处**：① yolo 的 imgsz 开大 + conf 放宽（召回主杠杆）；② seq_filter 的防抖只做"确认"，不做过严的过滤，避免把真目标筛掉。
- 若你还要**出图**（画框帧/目标子图），可在 yolo 后加 `annotate`（画框）或 `target_crop`（裁子图）——但注意 `target_crop` 只喂二次识别、`annotate` 只喂 VLM，**不改变检测结果**，对"不漏"无帮助，属可选。
- 若还要 **VLM 研判**（如"判断是否聚集/是否特定目标"），需在 yolo 后加 `annotate` 再挂 `vlm`，且**先定输出词表再写提示词**。
