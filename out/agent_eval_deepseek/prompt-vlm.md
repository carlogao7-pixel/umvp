# prompt-vlm  (prompt)

> 场景：让 VLM 顺便识别画面里有没有人吸烟，输出词表该怎么定？
> 关注点：VLM 提示词 + 词表对齐

先说结论：**词表不是"顺便加一句"就能定的，它是整条链路里最需要先钉死的东西**——因为 VLM 的输出词表必须和下游事件尾的判定条件**逐字对齐**，否则告警命中率直接归零。

## 一、机制上的关键约束（决定了词表怎么定）

1. **VLM 看的是"画框整图"**，输入必须来自 `annotate`（画框帧），不能是子图/人脸照。所以链路里 VLM 前面**必须先有 annotate 阶段**——这是"结构即声明"。
2. **先定词表，再写提示词**：`prompt` 里声明的输出词表，必须和事件尾（`det_filter.events` / `seq_filter.rules`）里的判定条件**用同一套字面量**。比如 prompt 要求输出 `吸烟/未吸烟/正常`，下游条件才能写 `label in 吸烟`。词表外自由发挥 = 命中率归零。
3. **VLM 不是检测器**：它只做"整图语义研判"（在干嘛/行为/警情），找框是 yolo 的活。所以"有没有人吸烟"这种**行为研判**正好是 VLM 的菜，但**别指望它给框**。

## 二、词表怎么定（业务建议）

**核心原则：词表要"封闭、互斥、可判定"，且和告警口径一一对应。**

针对"吸烟"这个诉求，建议词表按**告警类别**来定，而不是按"是/否"：

- 推荐形态：`吸烟 / 正常`（二分类，最简，命中即告警）
- 若画面里还有其他行为要一起研判，可扩成多类：`吸烟 / 打电话 / 正常`（互斥，下游按 `label in 吸烟` 命中）

**几个必须注意的点：**

| 要点 | 说明 |
|---|---|
| **字面量唯一** | 词表里每个词只能有一种写法，下游条件必须**逐字复制**，不能一个写"吸烟"一个写"抽烟" |
| **互斥不重叠** | 别出现"吸烟"和"疑似吸烟"两个都能命中的词，否则事件重复 |
| **留兜底类** | 一定要有"正常/其他"这类兜底，避免模型自由发挥出词表外的词 |
| **口径写进 prompt** | prompt 里要明确"只从以下词表中选一个输出：吸烟/正常"，并说明判定标准（如"手持香烟或口含香烟即判吸烟"） |

## 四、需要你确认的两点（定了才好落地）

1. **告警口径**：是"只要出现吸烟就报"，还是"持续 N 秒/多帧确认才报"？（后者要在 seq_filter 加时序确认，能压误报）
2. **词表范围**：只判吸烟，还是顺带判其他行为（打电话/打架等）？多类的话词表要一次定全，避免后续改 prompt 又要动下游条件。
