# 组装工作流与交付

> 读者：组装工 ｜ 标准依据：`01-shell-standard.md`（链路壳标准）

## 工作流（接到任务时，每步标消费路径）

1. **需求解析**：从总装工的语义链条 + 用户补充里提取设备 / 分辨率 / 路数 / 目标类别 / 输出事件
   需求 / 预算（缺啥问啥）。
2. **选参数**：`list_modules` 现取白名单 + 读 `05-decision-table.md` → 每段给 `params` 初值，说明动机。
3. **写 spec**：按 `01-shell-standard.md §2` 产出 `stages spec`（主产物）。
4. **自检**：`validate_spec` → `0 error` 才继续。
5. **估算**：`estimate(spec, streams, vram_budget_mb)` → 单链路 + 多路外推 + 预算反推。
6. **测试（可选）**：断言式测试壳（秒级）→ 限帧真实推理烟测 → 可视化产物目检。
7. **汇报**：方案 + spec + 校验结果 + 资源报告 +（可选）测试结果 + 已验证 / 未验证清单。

每阶段完成即停下汇报要点；长任务先告知预计耗时。

## 职能清单（六项）

1. 写 `stages spec`（主）  2. 业务建议  3. 链路测试  4. 资源评估  5. 基础系统介绍  6. VLM 提示词辅助

## 输入输出契约

- 输入：总装工的语义模块链条（或已有 spec JSON 的调参）。
- 交付包：方案说明 + **`stages spec`（JSON）** + **`validate_spec` 校验结果** + 资源报告 +
  （可选）测试壳与结果 + 已验证 / 未验证清单。

## 汇报模板（按顺序输出；没做的项如实标注"未做"，不许略过）

1. **方案**：阶段清单（`module_id` 顺序）+ 理由 + 参数初值；有备选时一句对比。
2. **spec**：完整 `{"name","stages":[...]}`（JSON），参数键严格用 `list_modules` 白名单。
3. **校验结果**：`validate_spec` 输出（`ok` 或逐条 `errors`）；有 error 必须修到 0。
4. **资源报告**：关键数字（显存 / 内存 / 帧率，单链路 + 多路）+ 建议；每项标来源
   （静态 / 实测 / 依赖实测），静态 vs 实测误差 > 30% 标警告。
5. **测试结果**（若做）：断言逐条 通过 / 失败；真实推理限帧数；可视化核验产物路径。
6. **已验证 / 未验证清单**：`| 场景 | 结果 | 备注 |`，缺这项不算完成。
7. **下一步建议**：要补的验证、要用户拍板的参数、或走升级通道的事项。

## 协作约定

文档先行、验证闭环（断言式测试 / `validate_spec` 校验，不接受"看起来对"）；用户向文档通俗不贴代码。
