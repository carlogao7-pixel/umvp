# 拼装套路与扩展（新模块 / 新编排）

> 读者：组装工 ｜ 用途：复用既有能力的套路；以及**当出现新模块或新编排逻辑时，怎么演进**。

## 1. 拼装套路（模块复用模式）

- **零改动复用**：模块间不强耦合（鸭子类型传入；如识别链阶段只需实现约定接口）。
- **参数即配置**：差异收敛为链路 `stages` 的参数，不写分支代码。
- **报送 / 事件粒度约定**：报送按识别类别分组（一类一条）；输出事件由事件尾
  （`seq_filter.rules` / `det_filter.events`）产出，一条记录可多事件；`cooldown<0` = 同对象一次。
- **胶水最小化**：新增逻辑只进"胶水文件"，核心模块只读。

## 2. 胶水文件套路（先例：裁剪 / 检测的拆分）

- 现有模块零改动；新增逻辑全在胶水 / 模块里（如坐标还原 + 原分辨率出图）。
- 编排函数串模块（例：`目标裁剪` 按 YOLO 框裁子图 → 识别模块 `FaceStage`/`extract_plates`
  在子图里检脸 / 检牌 → 坐标还原 → 原图出小图）。
- 配一个测试壳：断言 + 落盘产物（annotated.png 级）供目检。
- 判断"要新增胶水 vs 改模块"：优先零改动复用；要新增时说明成本（行数级）再动手。
- **通用能力已沉淀**：`pipe/cropper.py`（按框裁图可缩放 / 坐标还原 / 原分辨率提取）、
  `pipe/target_crop.py`（目标裁剪模块）、`pipe/conditions.py`（框筛选 DSL）、`pipe/annotate.py`
  （标注）；新链路凡涉及"按上游框裁图 + 坐标还原"直接用目标裁剪，别再造轮子。

## 3. 图像旁路：槽位判定与新模块接入（三级）

> 背景：数据流两流模型（JSON 主干 + 图像旁路）。构建链路（写 spec）层面**零图像编排**——
> 图衔接由壳固定编排，"结构即声明"。只有新产出类型复用不了既有旁路时才需开发介入。

**新模块带图像需求时，三级判定（从轻到重）**：

| 级别 | 判定 | 先例 |
|---|---|---|
| ① 参数级差异 | 需求 = 既有产物的不同加工，加工点已存在 | VLM `max_resolution` |
| ② 驱动层胶水 | 只有**一个**消费者，驱动层拿得到原料 | `_vlm_material`（取图 / 缩放 / 编码在运行器） |
| ③ 新增槽位 | 产出要给**多个 / 未知**下游，或它须成为链路**阶段**（spec 可见 / 可参数化 / 被校验） | `crop` / `annotate` / `plate` / `face` 四槽位 |

**判据**：驱动层能私下解决就②；需要成为链路结构的一部分才③。既有槽位先查重：
`last_annotated`（画框图→VLM）/ `last_crops`（子图→车牌 / 人脸，或 VLM `image_source=crops`）/ frame（原帧→裁剪 / 标注）。

**真到③，新模块接入清单（端口协议版）**——按此四步接入；**②③完成（"登记声明"）后，装配器 /
设计器即可用**，不必再改 `Pipeline` 核心：

1. **`Pipeline` 插槽（逐帧阶段）**：核心加字段 `xxx: Optional[object] = None` + 产物 `last_xxx`，
   并在 `step()` 固定位置调 `run(...)`（顺序参照既有流水）；
2. **模块声明 `INPUTS` / `OUTPUTS`**：类属性写清消费 / 产出的**端口名 → 类型**
   （`Image` / `Records` / `Vector`），如
   `INPUTS = {"image": "Image", "dets": "Records"}`、`OUTPUTS = {"annotated": "Image"}`
   （端口协议见 `01-shell-standard.md §3`）；
3. **`CHAIN_ASSEMBLED_MODULES` 登记**（`web_lab/server.py`）：登记 `module_id`，装配器
   `_chain_from_spec` 才会把它装进执行路径——这也是 `validate_chain`「声明即执行」断言的唯一依据；
4. **（可选）把端口纳入 `inputs` 解析**：让该端口的 `spec.inputs` 连线真正生效
   （核心 `_port(...)` 调用点 + `CHAIN_RESOLVED_PORTS` 登记）。**不纳入**则阶段仍可声明、仍参与
   其余校验，但 spec 写它的 `inputs` 只给**警告**、运行时按默认取数。

> **"登记声明后装配器 / 设计器即可用"**：完成 **②③**，新模块即自动出现在 `list_modules` 与设计器
> 模块列表（端口 schema 现取模块 `INPUTS/OUTPUTS`）；**④** 决定它的端口能否被 spec **显式连线**
> （未纳入的端口设计器不开放连线）。另有配套：模块参数表（`MODULES/PARAMS`）+ `doc/modules/` 分册；
> **产出要给驱动层落盘 / 展示**时，才需加驱动层取图分支（如 `base = pipe.last_xxx or ...`）。

> 组装工**不做**上述 1–4 的代码改动（那是升级通道）——但要知道它们的存在，才能判断"现有模块
> 拼不出来"并向总装 / 用户如实上报，而不是硬拼。

## 4. 新模块出现时

- **无需改本文档**：`list_modules` 会自动包含新注册模块；`validate_spec` 会按新模块参数表校验。
- 若新模块是一个**新阶段**（spec 可见）：照 `01-shell-standard.md §2` 用它的 `module_id` 与参数；
  终段白名单若有变化，以 `validate_spec` 的实际报错为准（规则由代码持有）。
- 若新模块引入**新旁路槽位**：参照 §3 的「新模块接入清单（端口协议版）」理解数据流变化；
  它声明 `INPUTS/OUTPUTS` 并被登记后，装配器 / 设计器即自动可用。

## 5. 资源估算速用

- `estimate(spec, streams=N, vram_budget_mb=B)`：单链路（显存 / 内存 / 帧率）+ 多路外推 + 预算反推。
- 每项标注来源（静态 / 实测 / 依赖实测）；静态 vs 实测误差 > 30% 标警告。
- 公式与指纹细节在 `umvp/resources.py` 与 `out/fingerprints.json`（换机 / 换卡后重跑标定）。

## 6. VLM 提示词辅助要点

- 从业务需求起草 `vlm.prompt` 初稿，给 2–3 版候选（简洁 / 严格 / 带示例）说明取舍。
- **词表对齐（关键）**：事件尾（`seq_filter.rules` 的 `match`，如 `label in 治安类|交警类`）按 VLM
  返回的 action 字符串**精确匹配**——提示词输出词表必须与规则 `match` 对齐，一并给出匹配建议。
  撰写顺序：**先定词表、再写提示词**。
- 提示词效果需实测（真 VLM 或模拟 infer），标注"依赖实测"。
