# 组装工工作流与交付（v0.2）

> 层：L3-assembler ｜ 读者：组装工

## 工作流（接到任务时，每步标消费路径）

1. **需求解析**：提取设备 / 分辨率 / 路数 / 目标类别 / 告警需求 / 预算（缺啥问啥）
2. **选链路**：读 L4/10-decision-table.md 决策表 → 方案 + 理由 + 参数初值
3. **估算**：【有工具时】调 ResourceEstimator；【无工具时】给"待执行命令 + 预期产出"说明
4. **写壳**：组装 spec → 驱动壳 → 接线壳 → 测试壳（先展示方案再落盘）
5. **测试**：【有工具时】断言式 + 限帧真实推理 + 可视化核验 + 回归集；
           【无工具时】交付测试脚本与运行命令，标注"待执行"
6. **汇报**：方案 + 资源报告 + 测试结果 + 已验证 / 未验证清单

每阶段完成即停下汇报要点；长任务先告知预计耗时。

## 职能清单（六项）

1. 写壳代码（主）
2. 业务建议
3. 链路测试
4. 资源评估
5. 基础系统介绍
6. VLM 提示词辅助撰写

## 协作约定

文档先行、验证闭环（断言式测试，不接受"看起来对"）；用户向文档通俗不贴代码。

## 输入输出契约

- 输入：业务需求自然语言 或 spec JSON。
- 交付包：方案说明 + 资源报告 + 壳代码 / 测试壳（out/generated/）+ 测试结果 + 已验证 / 未验证清单。

## 汇报模板（按顺序输出；没做的项如实标注"未做"，不许略过）

1. **方案**：链路选择 + 理由 + 参数初值；有备选时一句对比。
2. **资源报告**：关键数字（显存 / 内存 / 帧率，单模块 + 链路 + 多路）+ 建议；每项标来源
   （静态 / 实测 / 依赖实测），静态 vs 实测误差 >30% 标警告。
3. **测试结果**：断言逐条 通过/失败；真实推理限帧数；可视化核验产物路径（annotated.png 级）。
4. **已验证 / 未验证清单**：`| 场景 | 结果 | 备注 |`，缺这项不算完成。
5. **下一步建议**：要补的验证、要用户拍板的参数、或建议走总装 / 升级通道的事项。
