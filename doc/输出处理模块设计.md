# 输出处理模块设计（告警模块通用化）

> 状态：✅ 已实现（2026-09-22）｜ 代码落点：`umvp/pipe/composer.py`（`OutputPolicy`，`AlarmPolicy` 兼容别名）
> 实测：`test_composer.py` 60 断言；PIPE0002 真视频端到端告警 1 条
> （`触发 inspection（conf 0.83） — 京ACJ0710 绿牌新能源 0.83`）
> 背景：alarm 模块为「VLM 词表匹配 + 滑窗 + 冷却」而生；在车牌链路（kind=inspection）
> 7 个参数只有 kind/task_id 是活的，`alarm_cooldown` 等落库却永不生效（inspection 分支
> 不进冷却逻辑），车牌频率实际由 `Pipeline._plate_gate`（同车牌终身一次）+ 车牌阶段
> track 去重两处硬编码控制，语义分裂。

## 1. 统一抽象

多帧视觉分析的输出判定，本质是同一条流水线：

```
识别到对象 → 驻留时间足够 → 识别对象特征 → 置信度足够 → 去重/冷却 → 输出（告警/记录）
```

现有三种 kind（window / dwell / inspection）只是这条流水线上不同闸门的开关组合。
改造方向：把 AlarmPolicy 升级为**通用输出策略（OutputPolicy）**，任何识别来源
（YOLO / VLM / 车牌 / 人脸）都以统一事件进入，按同一组参数过滤后以统一事件输出。

## 2. 统一事件模型

### 2.1 输入：Finding（一次发现）

| 字段 | 类型 | 说明 |
|---|---|---|
| key | str | **对象标识**（去重/驻留记账的键）：`t:12`（track）、`plate:粤ACJ0710`、`cls:2:交警类`、`scene` |
| label | str | **主分类标签**：VLM action 词 / 车牌号 / `inspection` / `dwell:2` |
| conf | float | 置信度（默认 1.0）：车牌 score / VLM 无则 1.0 |
| features | dict | **特征包**（原样透传到输出事件）：车牌号、颜色、类型、VLM 描述、框坐标、plate_img 等 |
| ts | float | 帧时间戳 |

驻留不进 Finding——由模块内部按 key 维护 first_seen/last_seen 自行计算。

### 2.2 输出：OutputEvent（AlarmEvent 超集）

现有字段（task_id / gran / key / action / ts / description）不动，追加
`conf`、`features`。`AlarmEvent` 保留为别名，消费方（运行器时间线、落盘、告警展示）零改动。

## 3. 处理漏斗（七道闸，全部可关；默认组合 = 旧行为，零回归）

闸序：①登记 → ②驻留 `min_dwell` → ③词表 → ④置信度 `min_conf` → ⑥规则 `rules`
→ ⑤滑窗 → ⑦去重冷却 `key_cooldown`（"命中" = 通过 ③④⑥ 的 Finding，供滑窗计数）。

**各闸参数、默认值、规则 DSL 语法与示例的权威说明见 `doc/modules/输出处理.md` §2/§2.4**
（模块分册为准，此处不再复制，避免两处维护漂移）。要点：

- 新增闸：④置信度、⑥规则（自定义条件）、⑦按对象去重；`kind` 保留为预设档位
  （window / dwell / inspection = 不同闸门组合）。
- 规则闸面向仪表盘读数、越限告警等场景：识别模块把结构化读数放进 `features`，
  输出阶段只填一行 `features.reading >= 80` 即得越限告警，零代码。
- 安全：自研解析器无 eval，字段/操作符白名单，非法表达式保存/装配时快速失败；
  `features.<字段>` 缺失视为该条不通过。

## 4. 各链路接入映射

- **警用无人机（VLM）**：Finding(key=类别/场景, label=action, features={description})
  → 词表+滑窗+按 label 冷却（行为不变）。
- **车牌识别**：Finding(key=`plate:车牌号`, label=车牌号, conf=score, features=车牌特征包)
  → 全收 + 按 key 只输出一次（等价原 `_plate_gate`，行为不变；`key_cooldown>0`
  可选开启“同车牌 N 秒后再报”，默认关）。
- **驻留（small_only）**：Finding(key=track_id, label=`dwell:{cls}`) → 驻留+按类冷却（不变）。
- **人脸截取**：不接输出阶段（维持无告警）。

各链路 Finding 的构造点与字段细节见 `doc/modules/输出处理.md` §5。

## 6. 兼容承诺

1. 三条已播种链路（PIPE0001/0002/0003）**参数零改动、行为逐条等价**（上表第 4 列）。
2. `AlarmPolicy`/`AlarmEvent`/`on_vlm_result`/`on_dwell` 名字保留（别名/薄包装），外部调用零改动。
3. `alarm_cooldown` 在 inspection 下仍默认不生效（等价只一次）；「同车牌 N 秒可再报」是**显式开启才有的新能力**。
4. `rules` 默认空 = 全过闸，不改变任何现有行为；非法表达式在保存/装配时快速失败并报通俗错误。
5. 资源估算不受影响（无模型加载）。

## 7. 拍板结论（2026-09-22）

1. 「同车牌冷却后可再报」**默认关**：`key_cooldown` 默认 -1（同对象只输出一次），
   AL0002 不动、行为零回归；需要时在 web 端把 key_cooldown 设为 >0 即得 N 秒后再报。
2. 模块展示名改为「输出处理（告警）」；`module_id` 保持 `alarm`、preset 名不变
   （表名/接口零联动）。
3. 规则语法采用**字符串 DSL**（符号操作符 + 逗号 AND / 分号 OR，操作符两侧留空格），
   自研解析器无 eval、非法表达式快速失败。
