# 帧管理 FrameManager

> 模块组：管道四模块 | 代码：`umvp/pipe/composer.py`（`FrameManager`）
> 数据库参数：`FM0001`「警用无人机·帧管理」（presets 表 + preset_params_frame_manager 表）

## 1. 模块定位

决定"哪一帧需要分析"的节奏控制器：三种取图节奏（随抽帧/按墙钟秒/按帧数）+
两种背压（队列积压/推理耗时自适应），分析节奏跟不上时自动放宽抽帧间隔、
消化后恢复。链路中位于最上游，驱动后续 YOLO/VLM 只在"要图"的帧上工作。

## 2. 参数

### 2.1 模块自身参数（构造参数，落库为 preset）

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| sampling | select | analysis | 取图节奏：`analysis`=随抽帧节奏（含背压）；`wall_clock`=按墙钟秒；`frame_count`=按帧数 |
| frame_skip | int | 3 | analysis 模式基础抽帧间隔：每 N 帧取一张；积压时自动放大 |
| interval_sec | float | 3.0 | wall_clock 模式：每隔多少秒取一张 |
| interval_frames | int | 30 | frame_count 模式：每隔多少帧取一张 |
| queue_threshold | int | 32 | 队列背压：积压深度超过它触发放宽抽帧 |
| backpressure_multiplier | int | 2 | 放宽时抽帧间隔放大倍数（也是恢复时的收缩因子） |
| max_frame_skip | int | 空 | 放宽上限；空=自动（基础×倍数×4） |
| adaptive_relax_ratio | float | 1.2 | 自适应背压：推理耗时 > 预算×此值 → 放宽 |
| adaptive_recover_ratio | float | 0.5 | 自适应背压：耗时 < 预算×此值 → 逐步恢复基础间隔 |

### 2.2 测试参数（仅模块测试页运行用，不落库、不进链路）

`mode`（背压演示模式 queue/adaptive）、`scenario`（模拟场景：平稳/积压浪涌/耗时渐增）、
`fps`（预算估算帧率）、`n_frames`（模拟帧数）、`ts_step`（模拟时间步长）。

### 2.3 当前库内值（FM0001）

`sampling=analysis, frame_skip=15, interval_sec=3.0, interval_frames=30,
queue_threshold=32, backpressure_multiplier=2, adaptive_relax_ratio=1.2,
adaptive_recover_ratio=0.5`

frame_skip=15 为警用无人机远角视频实调值（约 0.5s 取一帧 @30fps）。

## 3. 输入（必要字段）

帧管理本身**不消费图像像素**，只接收帧的元信息做决策：

| 字段 | 类型 | 内容 |
|---|---|---|
| frame_idx | int | 帧序号（从 0 递增） |
| ts | float | 该帧的时间戳（秒，来自视频流） |
| pending | int，可选 | 队列积压深度；传入即启用队列背压，不传走自适应/纯抽帧 |
| cost_sec / budget_sec | float | `note_inference()` 的耗时反馈：本次推理实际耗时 / 帧间隔预算（秒），自适应背压据此调整 |

## 4. 输出（字段和内容）

| 输出 | 类型 | 内容 |
|---|---|---|
| wants_frame/decide 返回值 | bool | 该帧是否需要取图分析（链路主输出，驱动整条链） |
| current_skip | int | 当前生效的抽帧间隔（放宽时会大于基础值，可供观测） |
| relaxed | bool | 是否正处于放宽状态 |
| relax_events | int | 累计触发放宽的次数 |
| budget(fps) | float | 按当前间隔，两次分析之间的可用时间预算（秒） |

## 5. 上下游衔接

- 上游：视频解码循环（test.html 链路运行器 / FaceMonitor 等取帧层）。
- 下游：`wants_frame()==True` 的帧才交给 YOLO 识别；推理耗时通过
  `note_inference()` 回喂形成闭环。
