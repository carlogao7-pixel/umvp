# 检测筛选 DetFilter

> 模块组：管道模块 | 代码：`umvp/pipe/det_filter.py`（`DetFilter`；条件引擎
> `umvp/pipe/conditions.py`，记录适配 `umvp/pipe/records.py`）
> 状态：**2026-10 已承接 YOLO 有效性过滤；三条保留链路均在 YOLO 之后显式插入本阶段
> （PIPE0001→DF0001 / PIPE0002→DF0002 / PIPE0003→DF0003），YOLO preset 的有效性参数
> 已删除；web 端已注册模块测试页 + 链路设计器阶段（preset 前缀 `DF`）**
> 数据库参数：`preset_params_det_filter`（`DF0001+`）

## 1. 模块定位

通用下游筛选器：插在任意模块之后，对其输出列表做**有效性筛选**——逐条条件
（范围大小比较 + 条件间**与 / 或 / 非**组合，字段名灵活：别名 + 派生宽高尺寸量）
+ 成组数量判定（按类别计数，越界/未登记整类剔除）。只取舍、不改内容：放行元素
原样返回（对象进对象出、dict 进 dict 出），链路上透明插入、对所有下游一致生效。

它是"YOLO 输出纯 Detection、有效性过滤外移"方向的承接模块（决策记录：
选材参数保留在消费模块 ①A；命名 DetFilter ③；Record 适配器路线 ④A）。
经 `to_record` 统一字段视图后判定，因此可作**几乎所有模块**的下游——上游是
YOLO（list[Detection]）还是产出 dict 记录的模块（车牌/人脸/裁剪结果）都能筛。

## 2. 参数

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| filter | str | 空 | 条件 DSL（见下）；空 = 全放行。非法条件在构造时抛 ValueError（装配期快速失败） |
| group_limits | dict | None | 类别 → (数量下限, 数量上限)：**成组数量判定**，越界或未登记类别整类剔除（视为未识别）；`None`=不判定；显式空 dict=全拦（程序化构造时用；web/链路空值一律 None） |
| predicates | list | 空 | 代码级谓词链（可选，按序 AND 叠加在 DSL 之后）——`compose()` 的自定义过滤链等高级用法；DSL 能表达的场景不必用它 |

> 装配：链路上本阶段紧随 YOLO，是有效性过滤的**唯一来源**；`web_lab.server._det_filter_of()`
> 由 preset 参数构造 `filter`/`group_limits`。详见 [YOLO识别.md](YOLO识别.md) §2.3。

### 条件 DSL 语法（conditions.py，v2）

- 条件 = `字段 操作符 值`；操作符 `== != > >= < <= in`（`=` 等价 `==`；`in` 值用 `|` 分隔）
- 组合：组内逗号 `,` = **并且**；组间分号 `;` = **或者**；`not` = **非**（可连用
  `not not`）；`(` `)` 分组（括号内可再写 `,` / `;`，任意嵌套）
- 值本身含 `, ; )` 时用引号 `'` `"` 包住；数值条件按数字比较，否则按字符串比较

字段表（别名 → 标准名；不绑定来源，dict 键或对象属性皆可）：

| 字段 | 别名 | 说明 |
|---|---|---|
| cls_id | class / cls / 类别 | 类别编号（COCO：0=人，2=车） |
| track_id | track / id | 跟踪 ID |
| score | conf / 置信度 | 置信度 |
| w / h | width / 宽；height / 高 | **派生**：从 bbox 算宽 / 高 |
| short / long | 短边 / 长边 | **派生**：框的短边 / 长边像素 |
| area | 面积 | **派生**：宽 × 高 |
| ts | 时间戳 | `run()` 注入的帧时间戳 |
| frame_idx | 帧号 / frame | `run()` 注入的帧序号 |
| 其余字段 | — | 记录自带字段直接引用（label / text / kind / plate_no…） |

**聚合谓词**（同帧计数，与逐条条件同语法、可任意组合）：

| 写法 | 含义 |
|---|---|
| `count(字段)` | 当前记录在**该字段值**上的同帧分组大小（如 `count(cls_id)` = 同帧同类个数） |
| `count(子条件)` | 同帧满足该子条件的记录数（帧级常量，对所有记录一致） |
| `count()` | 同帧记录总数 |

- **"同帧"判定 = `run()` 调用边界**：一次 `run()` 的入参就是该帧全部检测（Pipeline 每
  分析帧调一次），无需从数据推断；若入参跨帧混入且记录自带 `frame_idx`，按 `frame_idx`
  二次分组（各帧独立计数）。
- 对同组记录返回相同值 → **整组同进同出**，保持"只取舍"契约。
- 子条件里**不再支持嵌套 `count`**；无聚合上下文时（目标裁剪/标注的逐框筛选）`count`
  取不到值 → 该条件不通过。

> `group_limits` 与 `count` 的关系：前者是"按类数量上下限"的**便捷参数**（未登记类别
> 剔除），后者是通用聚合谓词；两者可共存（AND）。`group_limits={0:(1,300)}` 近似
> `cls_id == 0, count(cls_id) >= 1, count(cls_id) <= 300`。

示例：

```
"score >= 0.5"                          置信度下限
"cls_id in 0|2, short >= 30"            人/车 且 短边≥30 像素
"not cls_id == 2"                       排除车
"not (cls_id == 0, score < 0.5)"        非（人且置信不足）
"(cls_id == 0; long >= 60), ts >= 10"   (人 或 长边≥60) 且 10 秒后
"count(cls_id) >= 2"                    同帧同类≥2 才留（轻量成组判定）
"count(cls_id == 0, score >= 0.5) >= 2" 同帧"人且置信≥0.5"的≥2 才留
"count(cls_id == 0; track_id == 3) <= 5" 同帧满足该 OR 子条件的≤5 才留
"count() <= 100"                        同帧总量上限（超了整帧都不留）
"not count(cls_id) >= 2"                同帧同类<2 才留
```

## 3. 输入（必要字段）

| 字段 | 类型 | 内容 |
|---|---|---|
| dets | list | 元素为任意对象或 dict（Record）：Detection、车牌/人脸/裁剪产物、通用记录 |
| ts | float | 帧时间戳（注入记录供条件引用，可省略） |
| frame_idx | int | 帧序号（同上） |

> 通用记录（Record）约定：模块逐帧输出 = list[dict]，必备 kind/ts/frame_idx，
> 通用字段 bbox/score/cls_id/track_id/label/text，旁路字段 image/embedding
> （像素与向量不进 JSON）。见 `umvp/pipe/records.py` 模块头注释。

## 4. 输出（字段和内容）

放行元素组成的子集（`list`）——**原元素原样返回**，不构造新对象、不改字段；
上游是 Detection 出来就是 Detection，是 dict 出来就是同一个 dict。

## 5. 上下游衔接

- 上游：任何产出 list[Detection] 或 list[Record] 的模块（YOLO `infer()` 最典型）。
- 下游：目标裁剪 / 标注 / VLM 报送编排 / 输出处理——本模块不改数据形态，
  下游无感知。
- 与消费模块选材参数的分工（决策 ①A）：本模块管**有效性**（不达标 = 该检测
  在链路上不存在，对所有下游一致）；TargetCrop/Annotator 自带的 classes/filter
  管**选材**（本阶段消费哪些存在的检测），两者 AND 叠加、互不取代。

## 7. 调参速查（通俗指南）

- **碎框/小目标太多** → `short >= 30` / `long >= 40`（等价旧 min_short/min_long）。
- **低置信噪声多** → `score >= 0.5`（等价旧 filter_conf）。
- **只想关注部分类别** → `cls_id in 0|2`；**排除某类** → `not cls_id == 2`。
- **多条件组合** → 括号 + 逗号/分号：`(cls_id == 0; long >= 60), area > 100`。
- **一段时间后才处理** → `ts >= 10`（配合 run 的 ts 注入）。
- 条件写错（缺操作符/括号不闭合/值为空）在**装配时就报错**，不会带到运行时。

## 9. 优化项（通用化思路，待排期）

> 目标：把现有"`字段 操作符 值` + 与/或/非 + `count(字段)`"升级为**表达式化的通用
> 判定引擎**：两侧放开为表达式、关系运算分类型、逻辑连接不变；单帧聚合与跨帧时序
> 分层，并共用同一引擎。

### 9.1 统一模型：值表达式 → 关系运算 → 逻辑连接

现状条件是"左侧固定字段名、右侧固定常量"。通用化把**两侧都放开为表达式**：

```
<左表达式> <关系运算> <右表达式>        （多条再用 , / ; / not / () 组合）
```

**(1) 表达式（左右两侧可用）**

| 类别 | 内容 | 对应诉求 |
|---|---|---|
| 字段值 | cls_id / track_id / score / label / text / kind…（含别名） | 已有 |
| 派生尺寸量 | w / h / short / long / area | 已有 |
| **坐标运算** | cx=(x1+x2)/2、cy=(y1+y2)/2、x1/y1/x2/y2、宽高、边距… | ① 坐标字段值运算 |
| **数值运算** | 四则 + 函数：`score*2`、`area/(w*h)`、`max(a,b)`… | ② 其他字段数值运算 |
| **聚合值** | `count(...)`（已有雏形）、`avg(...)`、`max(...)`、`min(...)`、`sum(...)` | ④ count 统计值判断 |
| 常量 | 数字 / 字符串 | 已有 |

**(2) 关系运算（按值类型）**

| 类型 | 运算 | 对应诉求 |
|---|---|---|
| 数值 | `== != > >= < <= in / between` | ①②④ |
| **字符串** | `== != contains startswith endswith matches`(正则) `in` | ③ 字符串关系运算 |
| 集合 | `in / not in` | 已有 |

**(3) 逻辑连接（已有，不变）**：`,` = 与、`;` = 或、`not` = 非、`()` 分组。

### 9.2 `count` 的语义：字段分组 vs 子条件计数（**已实现**）

- **字段分组**：`count(字段)` = "按该字段值分组，当前记录所在组的大小"，等价
  `count(字段 == 本记录该字段值)`；整组同进同出，适合"每类数量上下限"。
- **子条件计数（2026-10 已加）**：`count(子条件)` = 同帧满足该子条件的记录数（帧级
  常量，对所有记录一致）。子条件支持与/或/非/括号：`count(cls_id == 0, score >= 0.5) >= 2`、
  `count(cls_id == 0; track_id == 3) <= 5`。子条件里不再嵌套 `count`。
- 两者都在**单帧**作用域、可任意组合；`count()` = 同帧总数。下一步可把聚合扩为
  `avg/max/min/sum(<表达式>, [分组字段])`。

### 9.3 与「时序判定 SeqFilter」的分工（诉求 ⑤）

跨帧判断确实与 [时序判定.md](时序判定.md)（SeqFilter）重叠，须**分层不重复**：

| 作用域 | 归属 | 典型能力 |
|---|---|---|
| 单帧/批内 | **本模块 DetFilter** | count/avg/max、成组数量判定、坐标/数值/字符串条件 |
| 跨帧时序 | **SeqFilter** | 时间窗计数、连续 N 次、驻留时长、track 集合变化、事件标注 |

- 两者**共用同一条件/表达式引擎**（`conditions.py`）：DetFilter 每次 `run()` 携带
  单帧上下文，SeqFilter 携带跨帧状态；引擎扩展（表达式/字符串/聚合）一次实现、两处受益。
- 边界纪律：**不把时间窗/连续/跨帧塞进 DetFilter，也不把单帧分组计数塞进 SeqFilter**。

### 9.4 建议实施顺序

1. **字符串关系运算**（contains / startswith / endswith）——成本低、价值高。
2. **坐标 + 数值表达式**：把"固定字段左值"放开为算术表达式（cx/cy、四则）。
3. **`avg/max/min/sum` 聚合**（`count(<子条件>)` 已于 2026-10 完成，见 §9.2）：
   聚合值参与关系/逻辑判断。
4. **ROI / 区域命中**（框中心或框与矩形/多边形区域相交比）——需新增"区域"参数面与
   坐标归一化约定，单独小设计，不塞进条件字符串。
5. **跨帧项一律归 SeqFilter**，并让两模块引擎收敛统一（含 `parse_rules` 收敛）。
