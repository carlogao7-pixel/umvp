# 时序判定 SeqFilter

> 模块组：管道模块 | 代码：`umvp/pipe/seq_filter.py`（`SeqFilter` / `SeqRule`；条件引擎
> `umvp/pipe/conditions.py`，记录适配 `umvp/pipe/records.py`）
> 状态：**二期通用化（2026-10 决策）——独立模块，未注册 DB preset / web_lab 测试页**

## 1. 模块定位

通用下游**时序判定器**：对有序记录流按规则做"确认闸"——单条规则命中即放行、
窗口规则凑满次数才放行，放行时在记录上**标注事件字段**（事件不造新对象，跟着
证据记录走）。与「检测筛选 DetFilter」（单条条件、只取舍、对象透传）互补：

```
上游记录流（YOLO / 车牌 / VLM 结论…）
   │
   ▼
[检测筛选 DetFilter]   单条条件取舍（无状态，对象/dict 透传）
   │
   ▼
[时序判定 SeqFilter]   本模块：规则确认（有状态：窗口/冷却）+ 事件标注
   │
   ▼
裁剪 / 标注 / VLM / 输出物化（下游可按 event 字段筛取）
```

两种规则、一种形式（`span=0` 退化为单条语义）：

- **单条规则**：记录命中 `match` 条件 → 该记录放行并标注事件（= "能力 1 + 事件"，
  电平语义：每条命中都标）。
- **窗口规则**：同一 `key` 分组内，`span` 秒窗口里命中 `match` ≥ `min_n` 次 →
  第 n 条命中记录放行并标注事件（= "m 秒内出现 n 次"，N 次确认闸；未确认的
  中间命中由本模块扣留，边沿语义：达标一次放行一条）。

## 2. 参数

规则 `SeqRule`（列表传入 `SeqFilter(rules=[...])`，至少一条）：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| match | str | 必填 | 单条条件 DSL（语法/字段同检测筛选，含派生 w/h/short/long/area 与注入的 ts/frame_idx）；非法表达式装配期报错 |
| event | str | 必填 | 事件名：达成时写入记录的 `event` 字段（如 "驻留"、"高置信"） |
| key | str | track_id | 分组键（窗口计数、冷却抑制均按它分组；值缺失/None/0 归 `"*"` 组——无跟踪的记录同一窗内一起计数） |
| span | float | 0.0 | 窗口秒数 m；**0=单条语义**（命中即达成） |
| min_n | int | 1 | 窗口内命中 ≥ n 才达成（min_n>1 必须 span>0） |
| cooldown | float | 0.0 | 达成后的再触发抑制秒数（默认 0：窗口达标后即重臂，凑满新一轮 n 次即可再报；单条规则配它即事件节流） |

### 事件标注（输出记录上新增两个字段）

```
event      = 事件名（str，条件 DSL 可直接筛：event == 驻留 / event in 驻留|聚集）
event_info = {"key": 分组键值, "count": 达成时命中数, "span": 窗口秒, "ts": 达成时刻}
```

### 语义细则

- **规则有序、先匹配先得**：一条记录只被它匹配到的**第一条**规则认领——达成则
  放行标注；窗口未凑满则作为该窗口证据扣留；冷却期内则扣留。
- **窗口重臂**：达标后该 key 窗口立即清空重新计数（防帧帧重发）；`cooldown`
  在此之上额外按 key 抑制一段时间。
- **时间取值**：优先记录自带 `ts`（Record 约定），缺省用 `run()` 的 ts。
- **输出统一 Record（dict）**：输入可为对象（Detection）或 dict，内部经
  `to_record` 转换——事件标注要求可写字段，这是与检测筛选"对象透传"的唯一
  契约差异。

## 3. 输入（必要字段）

| 字段 | 类型 | 内容 |
|---|---|---|
| items | list | 有序记录（同帧或跨帧均可）：Detection / dict(Record) / 其它可适配对象 |
| ts / frame_idx | float / int | 时间上下文（记录自带 ts 时以记录为准） |

## 4. 输出（字段和内容）

放行记录组成的 `list[dict]`（Record）——命中单条规则的记录、或凑满窗口的
第 n 条记录，均带 `event` / `event_info` 字段；其余（未命中、窗口未凑满、
冷却期内）全部扣留。

## 5. 上下游衔接

- 上游：任意产出记录列表的模块；与 DetFilter 串联是标准用法（先取舍后确认）。
- 下游：按 `event` 字段筛取/物化（输出处理的替代形态：物化器把带 event 的
  记录转成 AlarmEvent/落盘，见输出处理.md §7 三期路径）。
- 与输出处理的分工（现期）：OutputPolicy 仍是三条在用链路的末端实现，本模块
  仅并行提供通用化形态；三期等价验证后切换。

## 7. 调参速查（通俗指南）

- **闪断误报多（YOLO 单帧噪声）** → 窗口规则：`span=5, min_n=3`（5 秒见到
  3 次才放行，等价滑窗确认）。
- **VLM 抖动** → key=label，match=词表命中，span/min_n 做连续确认。
- **驻留语义** → key=track_id，match=存在条件（如 `cls_id == 0`），span=驻留
  秒数、min_n≈span×帧率。
- **只想打标不想确认** → 单条规则（span=0），每条命中都带事件字段。
- **同一事件别刷屏** → 配 cooldown（按 key 抑制）。
- 车牌"连续读到才采信"：key=label（车牌号），match=`kind == plate`，
  span=3、min_n=2。

## 8. 边界与路线

一期/二期均**不做**（边界）：不修改事件字段以外的内容；不做"连续 n 次无中断"
语义（时间窗已覆盖主要场景，需要时加 `consecutive: true`）；不做跨帧聚合以外
的统计（均值/求和等，出现真实需求再议）；不构造 AlarmEvent（物化归下游）。

三期候选：与 OutputPolicy 的等价性验证与切换（输出处理.md §7）；DB preset /
web_lab 注册随 YOLO 迁移一并（检测筛选.md §8）。

**与检测筛选的分工（分层不重复，通用化思路见 [检测筛选.md](检测筛选.md) §9）**：
单帧/批内聚合（count/avg/max、成组数量判定）归 DetFilter；跨帧时序（本模块：时间窗、
连续 N 次、驻留、track 变化、事件标注）。两者共用 `conditions.py` 条件引擎，登记
"时间窗/连续/跨帧"类能力时只在本模块加，不塞进 DetFilter。
