# 输出处理（告警）OutputPolicy

> 模块组：管道模块 | 代码：`umvp/pipe/composer.py`（`OutputPolicy`，旧名 `AlarmPolicy` 为兼容别名）
> 数据库参数：`AL0001`「警用无人机·告警策略」/ `AL0002`「车牌识别·告警策略」（presets 表 + preset_params_alarm 表）

## 1. 模块定位

链路的**统一输出处理**：把任意识别来源的“发现”收敛成统一事件，经一条七道闸漏斗
过滤/确认/去重后输出（告警/记录）。多帧视觉分析的公共形态即：

```
识别到对象 → 驻留时间足够 → 识别对象特征 → 置信度足够 → 去重冷却 → 输出
```

车牌识别、VLM 警情、驻留事件都用同一条漏斗——差异只是闸门开关（`kind` 预设档位）
与参数值，不再各自硬编码。

## 2. 参数

### 2.1 模块自身参数（落库为 preset）

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| kind | select | window | **预设档位**：`window`=VLM 词表+滑窗+按警情冷却；`dwell`=驻留秒数+按类别冷却；`inspection`=全收+同对象只输出一次（车牌/巡检） |
| task_id | int | 1 | 任务编号，随事件带出（多任务/多路区分用） |
| target_actions | str | "fire,fight" | 词表（逗号分隔）：命中其一才放行；**空=巡检模式**（window 自动降级 inspection） |
| window_frames | int | 2 | 滑动窗口长度（仅 window 判定；连续几帧命中才输出） |
| hit_ratio | float | 1.0 | 窗口内命中比例达到多少才输出（1.0=全部命中，仅 window） |
| min_conf | float | 0.0 | **置信度闸**（0=关）：事件置信度低于它不输出（车牌=识别分；VLM 无分=1.0 不受限） |
| dwell_sec | float | 2.0 | **驻留闸**（仅 dwell 判定）：对象持续出现达到该秒数才输出 |
| rules | text | "" | **规则闸**（空=关）：对事件字段自定义条件，语法见 §2.4 |
| alarm_cooldown | float | 60.0 | 冷却秒数（window/dwell）：同 scope 冷却期内不重复输出 |
| key_cooldown | float | -1.0 | 仅 inspection：`-1`=同对象只输出一次（车牌默认）；`0`=不去重逐条落盘；`>0`=同对象 N 秒后可再报 |
| cooldown_by_action | bool | false | window：true=不同警情类型各自独立冷却；false=统一冷却 |

### 2.2 测试参数（仅模块测试页运行用，不落库、不进链路）

`timeline`（事件时间线文本，逐行喂入模拟事件验证判定逻辑）。

### 2.3 当前库内值

- `AL0001`（警用无人机）：`kind=window, target_actions="治安类,交警类,群体性事件类,救援救助类",
  window_frames=1, hit_ratio=1.0, alarm_cooldown=30.0, cooldown_by_action=true`
  ——与警用链路 VLM 提示词四类警情配套；窗口=1（无人机研判频次低，单次命中即成警）；
  30s 冷却按警情类型独立。
- `AL0002`（车牌识别）：`kind=inspection, target_actions="", alarm_cooldown=30.0,
  key_cooldown=-1` ——车牌按对象（车牌号）只输出一次；`key_cooldown>0` 可改为
  “同车牌 N 秒后再报”（默认关闭，行为与历史一致）。

### 2.4 规则 DSL（rules 参数）

条件 = `字段 操作符 值`；**组内逗号 = 并且，组间分号 = 或者**（命中任一组即过闸）；
操作符两侧必须留空格。

- 字段：`conf` / `dwell` / `label` / `key` / `features.<特征名>`（特征包里没有该字段 → 该条不通过）
- 操作符：`>= > <= < == != contains in`（`in` 的值用 `|` 分隔多选）
- 值：数字或字符串（含空格/特殊字符时用引号包住）

```
# 仪表盘读数越限（识别模块把读数放进 features 即得越限告警，零代码）
features.reading >= 80, features.unit == ℃
# 只报绿牌且高置信度的车牌
features.color == green, conf >= 0.9
# 描述含关键字，或分类命中词表
description contains 占道
label in 交警类|治安类
```

非法表达式在保存/装配时即报通俗错误（指明第几组第几条），不会静默失效。

## 3. 输入（必要字段）

统一入口 `accept(Finding)`；旧的 `on_vlm_result()` / `on_dwell()` 保留为兼容包装。

| 字段 | 类型 | 内容 |
|---|---|---|
| key | str/int | **对象标识**（去重/驻留记账键）：`plate:粤ACJ0710`、track_id、类别编号、`scene` |
| label | str | 主分类标签：VLM action 词 / 车牌号 / `dwell:{cls}` |
| ts | float | 事件时间戳（秒） |
| gran | str | 报送粒度（class/scene/track，默认 class） |
| conf | float | 置信度（默认 1.0；车牌=识别分） |
| features | dict | 特征包：车牌号/颜色/类型/框坐标/读数/VLM 描述等，原样透传到输出事件 |

驻留不单独传：模块按 key 记首次出现时间自行计算（`dwell = 当前 ts − 首次 ts`）。

## 4. 输出（字段和内容）

`accept()` → list[AlarmEvent]（空列表=未通过漏斗）：

| 字段 | 类型 | 内容 |
|---|---|---|
| task_id | int | 任务编号 |
| gran | str | 报送粒度（class/scene/track） |
| track_key | str/int | 对象标识（车牌时为 `plate:车牌号`） |
| action | str | 命中标签：警情类型 / `dwell:{cls}` / `inspection` |
| ts | float | 输出时刻（秒） |
| description | str | 摘要（VLM 描述 / 车牌摘要） |
| conf | float | 来源置信度（车牌识别分等） |
| features | dict | 特征包（原样透传，供落盘/上报） |

## 5. 上下游衔接

- 上游：VLM 研判结果（window/inspection）、YOLO 逐 track 事件（dwell）、车牌识别结果
  （inspection，`Pipeline.step` 构造 Finding 并带特征包）。
- 下游：链路末端，事件即链路最终输出（web 时间线/落盘）。
- 闸序：①登记 → ②驻留 → ③词表 → ④置信度 → ⑥规则 → ⑤滑窗（“命中”=通过③④⑥）
  → ⑦去重冷却。
