# 目标裁剪模块设计（TargetCrop）

> 状态：已实施（2026-09-23）｜ 关联：`umvp/pipe/cropper.py`、`umvp/pipe/target_crop.py`、
> `umvp/plate_recog/`、`umvp/face_detect/face_pipeline.py`、`web_lab/server.py`
> 目标读者：开发 / 链路组装

## 1. 背景

当前"裁剪"这件事散落在三处，且都不属于任何检测模型的能力：

| 位置 | 现状 | 问题 |
|---|---|---|
| YOLO 模块 `roi`（crop:cls） | 产出 `ref=crop:cls{n}`，真正裁剪在拼接层 `web_lab/server.py:_vlm_material` | 挂在 YOLO 模块上，实为拼接层行为，语义误导 |
| 车牌模块 `extract_plates` | 内部 `tool.crop(img, d.bbox)` 裁车（"第一次裁剪"，可放大） | 裁剪耦合进车牌识别，职责不清 |
| 原分辨率提取 `extract_faces` | 内部 YOLO 识人 + 裁人 + SCRFD + 原图出脸，一条龙 | 模块既检测又裁剪，不可复用；名不符实（输出不再只有原分辨率） |

**结论**：裁剪应抽为一个独立、通用、可复用的模块——**目标裁剪**：仅接收"原帧 + 坐标"，
按坐标裁出子图，输出分辨率可配（默认原分辨率），不含任何检测器。

## 2. 模块定义

- **模块名**：目标裁剪
- **module_id**：`target_crop`（业务 ID 前缀 `CROP`，如 `CROP0001`）
- **代码**：`umvp/pipe/target_crop.py`（复用 `umvp/pipe/cropper.py` 的 `Cropper`）
- **职责边界**：只做机械裁剪与坐标换算，**不跑检测器、不判类别语义、不做业务去重**
  （类别过滤仅是"裁哪些框"的入参）。

### 2.1 接口

```python
@dataclass
class CropResult:
    img: np.ndarray                    # 裁剪子图（按 scale 缩放后）
    bbox: Tuple[int, int, int, int]    # 实际裁剪框（原图坐标，含 margin，clamp 后）
    offset: Tuple[int, int]            # 子图左上角在原图坐标
    scale: float                       # 输出缩放倍数（含 resize；1.0=原分辨率）
    cls_id: int = -1                   # 来源检测类别（无检测时为 -1）
    score: float = 0.0                 # 来源检测置信度
    track_id: int = 0                  # 来源检测 track_id（有跟踪时）
    index: int = 0

def crop_targets(frame, dets=None, boxes=None, *,
                 scale=1.0, margin=0.0, min_short=0, classes=None) -> List[CropResult]:
    """按坐标裁图。dets=上游 Detection 列表（取 bbox/cls_id/score/track_id）；
    boxes=裸框列表（无检测元数据）。二者取其一。"""
```

坐标还原：下游（SCRFD / HyperLPR3）在子图坐标系里得到框后，
`原图框 = 子图框 / crop.scale + crop.offset`（复用 `Cropper.to_original` 语义）。

### 2.2 参数（模块 preset）

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| scale | float | 1.0 | 输出缩放倍数（1.0=原分辨率；>1 放大助小目标召回，<1 缩小省内存） |
| margin | float | 0.0 | 裁剪外扩比例（按框宽高外扩，clamp 到图边界） |
| min_short | int | 0 | 目标框最小长边（像素），更小则跳过 |
| classes | str | "" | 只裁这些类别（逗号分隔；空=全部） |

> 相比现车牌模块的 `upscale=2.0`，`scale` 支持 <1（缩小），并统一承担"输出分辨率"语义；
> `margin` 真正作用于"裁车"这一步（现车牌模块的 margin 实际只作用于裁车牌，帮助文本有误导）。

### 2.3 对 `Cropper` 的最小改动

`Cropper.crop()` 目前只在 `upscale > 1.0` 时放大。新增支持任意 `scale != 1.0`
（含缩小）的路径（新增参数或由 `crop_targets` 内部完成 resize，二选一，实施时定）。
`extract()`（原分辨率出图）保持不变。

## 3. 链路改造

### 3.1 车牌识别链路 PIPE0002

```
前：帧管理 → YOLO识车 → 车牌识别（内部：裁车放大 → 裁车牌 → 识别 → 还原）
后：帧管理 → YOLO识车 → 目标裁剪（裁车, scale=2.0, margin=0.1, classes=2）
                    → 车牌识别（只：从车图裁车牌 + 识别 + 还原坐标 + 原图出车牌小图）
                    → 输出处理
```

- `extract_plates(frame, crops, plate_rec, tool, dedup_iou)`：入参由 `dets` 改为
  `crops`（目标裁剪产物），不再自己裁车；用 `crop.offset/scale` 还原车牌框，
  仍从**原帧**按还原框裁出原分辨率车牌小图（存证）。
- `PlateStage.run(frame, crops, ts)`：按 `crop.track_id` 去重（`track_dedup/cooldown`），
  `classes` 过滤上移到目标裁剪。
- 车牌模块参数瘦身：去掉 `car_classes / upscale / min_car_short`（移入目标裁剪）；
  保留 `detect_level / dedup_iou / track_dedup / track_cooldown`，新增裁车牌 `margin`。

### 3.2 人脸截取链路 PIPE0003

```
前：帧管理 → YOLO识人 → 原分辨率提取 extract_faces（内部：裁人 → SCRFD → 原图出脸）
后：帧管理 → YOLO识人 → 目标裁剪（裁人, classes=0, min_short=30）
                    → 人脸检测（SCRFD 检脸 + 原图出脸）
                    → （人脸嵌入 → 向量底库，可选）
```

- `extract_faces` 模块取消：**裁人**（YOLO 框）由目标裁剪承担；**检脸 + 原分辨率出脸**
  留在**人脸检测模块**——与车牌识别模块"检牌 + 原图出车牌"同构，
  人脸/车牌的二次裁剪都留在各自识别模块内，不进链路 stages。
- 人脸检测模块需**原帧 + 目标裁剪的 offset/scale**，用于把脸框还原到原图坐标、
  再从原图直接裁出原分辨率脸图（`Cropper.extract`）。
- 含 `face_embed` 的"视频人脸检索"形态：人脸检测之后接 `face_embed` 做身份去重。

### 3.3 警用无人机链路 PIPE0001（VLM）

- 移除 YOLO 的 `roi`（crop:cls）——它不是模型能力，实际裁剪在拼接层。
- 需要 ROI 裁剪时：`帧管理 → YOLO → 目标裁剪 → VLM`（VLM 消费裁剪子图）。
- 不需要裁剪（送整帧）时不插目标裁剪。VLM 的 `crop_padding` 由目标裁剪的 `margin` 取代。

## 4. 数据/参数迁移

- 新增模块 `target_crop`（前缀 `CROP`）：注册参数 schema + `preset_params_target_crop` 表。
- 下线 `extract_faces` 模块：`db._PRUNED_MODULES` 增补，init_db 清理其参数表与 preset。
- 重新播种三条链路：
  - PIPE0002：YOLO0002 → **CROP000x（裁车）** → PLATE0002 → AL0002
  - PIPE0003：YOLO0003 → **CROP000x（裁人）** → FDET000x（检脸+原图出脸）
  - PIPE0001：YOLO0001（去掉 roi）→ VLM0001 → AL0001（默认不插裁剪，送整帧）
- 旧整数 schema 的自动 DROP/重建机制不变。
