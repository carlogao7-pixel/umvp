# 视觉识别链路定制系统 —— 需求文档（开发版）

> 面向开发者：技术设计、代码引用、接口定义。配套通俗版见《需求文档-业务版》。

## 一、背景与目标

UMVP 现有零散模块已齐备，但缺少三层能力：

1. **知识层**：`.claude/skills/face-extract-pipeline/SKILL.md` 目前只记录单条人脸提取链路（WIP 状态），需扩为覆盖全部链路的 skill 手册。
2. **智能层**：无 agent。需要一个新的 pipeline 规划/生成/测试 agent，以 skill 文档为知识底座。
3. **交互层**：`web_lab` 只能单模块测试，无"链路定制 + 资源估算"能力。

用户明确点出的缺失能力：**完整链路的 GPU/内存占用自动计算或估计**。本文档把四件事（skill / agent / web 服务 / 资源估算）统一设计，资源估算是贯穿三层的公共能力。

## 三、核心设计：资源估算（ResourceEstimator）

### 3.1 设计原则

- **静态法 + 实测法两层**。静态：不加载模型，秒级粗估；实测：真实推理标定，精确，结果缓存为 JSON。
- **统一资源指纹（ResourceFingerprint）**：每个模块暴露 `{vram_mb, ram_mb, latency_ms_cpu, latency_ms_gpu, fps@device}`。静态层按模型文件大小/参数量+输入分辨率估算；实测层跑基准写入指纹。
- **链路聚合**：链路 = 各模块按"每帧经过路径"聚合。注意部分模块**不是每帧都跑**（如 VLM 受 `check_interval` 节流、人脸嵌入只在检测命中后跑）——聚合必须按"每帧平均成本"而非简单相加。

### 3.2 数据结构

```python
# web_lab/resources.py（新增）或 umvp/resources.py（若需被 agent 复用，放 umvp/）
@dataclass
class ResourceFingerprint:
    vram_mb: float          # 显存峰值（含权重+激活+图）
    ram_mb: float
    latency_ms_cpu: float
    latency_ms_gpu: float
    note: str               # 条件说明（分辨率、batch、设备）

@dataclass
class PipelineEstimate:
    per_module: dict[str, ResourceFingerprint]
    vram_mb: float          # 链路显存 = 各模块峰值并集（GPU 上模型常驻取 max，激活取路径 max）
    ram_mb: float
    latency_per_frame_ms: dict[str, float]   # cpu / gpu
    fps_cpu: float; fps_gpu: float
    # 多路外推
    streams: int
    vram_mb_N_streams: float
    note: str
```

### 3.3 估算规则（v1 简化，可后续加精）

- **YOLO**：显存 ≈ 权重(fp16) + 激活(分辨率相关经验公式) + 图；帧耗时按实测指纹表（CPU 1.7s / GPU 0.02s，分模型与 imgsz）。
- **SCRFD(FaceDetector)**：onnxruntime session 常驻；按 det_size 与实测（CPU ~110ms@640）估。
- **ArcFace(FaceEmbedder)**：~10ms CPU / 更短 GPU；批处理可并。
- **FaceStore**：内存 ≈ 向量数 × 512 × 4B（numpy float32）；检索 <1ms，可忽略。
- **VLM**：本地只做素材准备（裁剪/缩放，开销小）；真实推理耗时 = 远端延迟，估算标"依赖实测"。
- **抽帧调度/告警策略**：纯逻辑，开销可忽略（标记为 0）。
- **多路外推**：模型常驻内存部分不随路数增长（共享）；激活/图/推理并发部分随路数线性增长；超过显存给 WARNING 并建议 `frame_skip`。
- **预算反推**：给定 `vram_budget_mb`，求解满足 `estimate.streams == N` 且总占用 ≤ 预算的最大帧率/最小 frame_skip；输出建议 `frame_skip`、`check_interval` 与预期 FPS。

### 3.4 指纹标定命令（实测层）

```bash
PY=/home/carloga0/miniconda3/envs/ai/bin/python
$PY web_lab/calibrate.py --out out/fingerprints.json   # 遍历 models/*.pt + face 模型，分别 CPU/GPU 实测一次
```

## 四、核心设计：链路定制 web 服务（扩展 web_lab）

### 4.1 扩展方式

**不新建服务，扩展现有 web_lab**（零依赖架构已被验证）。新增：

- **API**：
  - `GET /api/pipeline/schema`：可组合的模块清单（含"可接上游/下游"约束）。
  - `POST /api/pipeline/estimate`：body = pipeline spec，返回 `PipelineEstimate`（含多路推演与反推建议）。
  - `POST /api/pipeline/build`：body = pipeline spec，生成 `compose spec JSON + 测试脚本路径`（写入 `out/generated/`），返回可运行命令。
  - `POST /api/pipeline/run`：运行已生成链路（复用现有 `_TEST_LOCK` 串行执行）。
- **前端**：`index.html` 增加"链路设计器"视图——选模块 → 连线（链式为主，v1 不支持任意 DAG）→ 填参数 → 实时显示估算 → 生成/运行。复用现有 `renderResult()`。
- **pipeline spec（JSON）**：

```json
{
  "name": "巡检链路",
  "stages": [
    {"module": "frame_manager", "params": {"sampling": "wall_clock", "interval_sec": 1.0}},
    {"module": "yolo", "params": {"model_path": "yolov8n.pt", "classes": "0", "class_limits": "0:1,300"}},
    {"module": "vlm", "params": {"ref": "crop:cls0"}},
    {"module": "alarm", "params": {"kind": "window", "target_actions": "fire"}}
  ],
  "streams": 16,
  "budget": {"vram_mb": 8192}
}
```

### 4.2 与现有 API 的关系

现有 `POST /api/test/<module>` 单模块测试保持不变（回归安全）。pipeline 的 stage 参数校验直接复用各模块 PARAMS 定义（含新加的 help），保证"链路定制"与"单模块测试"参数口径一致。

## 六、核心设计：pipeline agent

### 6.1 定位

新 agent（建议 `subagent_type: pipeline-architect`，定义文件放 `.claude/agents/pipeline-architect.md`）：

- **输入**：自然语言需求（设备约束、分辨率、路数、要识别的目标、告警需求）。
- **工作流**：需求解析 → 读 skill 决策表选链路 → 调 ResourceEstimator 估算/反推 → 生成 pipeline spec + 测试脚本 → 跑测试（复用 web_lab API 或直接跑 pytest 风格脚本）→ 汇报（含资源报告与"未验证场景"清单）。
- **护栏**：改动任何 `umvp/` 模块代码前必须声明；每次交付跑回归集（27 断言 + 7/7 自检）确认不破坏现有链路。

### 6.2 agent 与 skill 的依赖

agent 只读 skill + 代码，不硬编码业务知识 → skill 更新即 agent 能力更新。skill 中"资源指纹"一节由 ResourceEstimator 的指纹 JSON 自动生成入口（标定命令写入手册）。

## 九、风险与未决问题

- **显存估算误差**：PyTorch 缓存分配器会让"实测峰值"大于公式值；以实测为准，公式只做粗筛。
- **多路并发估算**：v1 假设"模型常驻共享 + 激活线性"；实际多进程/多线程各有额外开销，需真机标定修正系数。
- **VLM 远端延迟**：无法本地估算，文档标注依赖实测。
- **agent 自主跑真实推理**：耗时（YOLO 秒级、三模式分钟级），需在 agent 约束里设超时与限帧约定。
- **skill 覆盖面**：人脸链路 skill 已有大量实测数据，四模式/监控链路的实测数据尚未整理成 skill 格式，需补充跑一遍。
- **是否抽象出 `umvp/resources.py`（web_lab 与 agent 共用）**：倾向放 `umvp/`，避免 web_lab 独占导致 agent 无法直接 import。
