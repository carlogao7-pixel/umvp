## 一、需求定位与集成形态

UMVP 现有 YOLO 模块已能检出车辆（COCO `car`=2）。车牌识别应作为**新的下游模块**接入，
形态类比人脸链路（YOLO 识人 → 裁人 → SCRFD 检脸 → 原分辨率还原）：

```
YOLO 识车(cls=2) → 裁车（远角可放大，复用 CropRestore 思路）
                 → 车牌检测/定位 → 车牌识别（字符 + 颜色/类型）
                 → 结构化输出 PlateResult{plate_no, plate_type, color, score, bbox}
                 →（可选）去重 / 送 VLM 复核 / 告警
```

关键约束（与项目既有约定一致）：

- **本地离线部署**，无外部端点依赖（VLM 直读仅作兜底）。
- **栈匹配**：优先 onnxruntime + opencv + numpy（项目唯一 conda 环境 `ai` 已有）。
- **模型自包含**：权重放进项目目录（同 `models/`、`face_models/` 模式），不依赖用户目录缓存。
- **中文车牌**为主：蓝牌 / 黄牌 / 新能源 / 警用 / 武警 / 双层等；警用无人机场景尤其关注
  **远角小车牌**与**新能源 8 位车牌**。

## 三、分档详评

### A. 中文车牌专用（最贴合场景）

**A1. HyperLPR3（`szad670401/HyperLPR`）** — 上轮调研的推荐起点

- 技术栈：`opencv-python` + `onnxruntime`，纯 Python，`pip install hyperlpr3`（v0.1.3，2023-02-28，Apache-2.0）。
- 流程：检测（Y5 结构）→ 四点矫正 → 识别（无需字符分割）→ 分类器判颜色/类型；双层牌自动上下分割。
- 中文支持：单行蓝/黄、新能源、教练（支持）；白警、使馆/港澳、双层黄、武警（有限支持）；民航、双层军/武警/农用（待支持）。
- 性能（README 自述）：720p 单核 Intel 2.2GHz CPU 平均 <100ms；出入口场景准确率约 95%–97%。
- **关键实现细节（本次实查源码确认）**：pip 包仅 23KB，**模型不在包内**——运行时从
  `http://hyperlpr.tunm.top/raw/` 下载到 `~/.hyperlpr3/<版本>/onnx/`，含
  `y5fu_320x/640x_sim.onnx`（检测）、`rpv3_mdict_160_r3.onnx`（识别）、`litemodel_cls_96x_r1.onnx`（分类）。
  离线部署需**先联网拉一次、再把模型拷进项目目录并改配置路径**（`config/settings.py`）。
- 短板：主包 2023 年后未发版（仓库 2025-02 仍有提交）；精度上限不如自训练；模型自包含需手工处理。

**A2. we0091234（`Chinese_license_plate_detection_recognition`）** — 中文覆盖最全

- 技术栈：PyTorch（YOLOv5/v7/v8 检测 + CRNN 识别 + 颜色分类），另提供 ONNX / TensorRT / OpenVINO / NCNN(安卓) 部署脚本。
- **支持 12 种中文车牌**：单行蓝/黄、新能源、白警、教练、武警、双层黄、双层白、使馆、港澳粤Z、双层绿、民航。
- 活跃（2026-06），有配套训练仓库与 `yolov8-plate`、`yolo26-plate` 等版本。
- **许可为 GPL-3.0**：对闭源商用产品是强 copyleft 风险（权重通常也被视为衍生）。仅适合内部研究，
  或作为**结构/数据参考**，不建议直接嵌入交付产品。

**A3. 其他中文项目**

- `zhubenfu/...`：README 自述中文 99.8%，但**无 LICENSE（默认保留所有权利）且 2020 停更**——不可用。
- `DataXujing/...`（MIT，2019）、`EasyPR`（Apache-2.0，传统 CV）、`light-LPR`（无许可）：
  年代较早或精度/许可不佳，仅作了解。
- `pcb9382/PlateRecognition`（MIT，2026-09）：多地区车牌 + TensorRT C++，面向嵌入式/商用，性能强；
  但技术栈是 C++/TensorRT，与项目 Python/ONNX 主栈不同，集成成本高。

### B. 检测 + OCR 可组合框架（工程规范，但默认非中文）

**B1. `ankandrew/fast-alpr`（MIT）+ `fast-plate-ocr`（MIT）** — 设计最现代

- `fast-alpr` 组合「车牌检测器 + OCR」：默认检测 `yolo-v9-t-384-license-plate-end2end`，
  默认 OCR `cct-xs-v2-global-model`（Compact Convolutional Transformer）。
- 纯 ONNX Runtime，多后端 extra：`onnx`(CPU) / `onnx-gpu`(CUDA) / `onnx-openvino` / `onnx-directml` / `onnx-qnn`。
- 延迟（fast-plate-ocr README，RTX 3090）：`cct-xs-v1` 约 0.32ms/张；检测器另有开销。
- **注意**：默认模型面向**拉丁字符/多国车牌**，**不含中文字符集**——直接用于中文车牌会读不出省份汉字。
  可用其框架替换为自训练中文 OCR 模型，但等于自研。
- 模型从 HuggingFace/GitHub Releases 拉取，同样需一次性缓存以实现离线。

**B2. `sirius-ai/LPRNet_Pytorch` / `xuexingyu24/...`** — 识别段与两阶段参考

- LPRNet 是经典轻量端到端识别网络（无需字符分割），`xuexingyu24` 用 MTCNN+LPRNet 在 CCPD 上自述 99%；
  适合作为**自训练识别段的骨干**参考。

### C. 国外 / 通用 ALPR

- `openalpr`（AGPL-3.0，欧美，Tesseract，需编译，2024 后基本停滞）：许可与场景均不合适。
- `sergiomsilva/alpr-unconstrained`：无约束场景，但面向巴西（灰度）车牌。
- `DoubangoTelecom/ultimateALPR-SDK`：速度强，NOASSERTION（商用授权），非中文专用。
- `parkpow/deep-license-plate-recognition`（MIT，C++/ONNX，2026 活跃）：可作为通用推理实现参考。

### D. 通用 OCR 栈（PaddleOCR 等）

- `PaddleOCR`（Apache-2.0）：中文 OCR 精度高、生态成熟，但需引入 **paddlepaddle 全家桶**，
  与项目现有 onnxruntime 栈重复且体积大；若已有 Paddle 环境可考虑，否则换栈成本高。

## 五、推荐路线

**第一步（快速落地）：HyperLPR3**

- 与项目栈一致（ONNX + CPU），一周内可出可用模块；许可 Apache-2.0 干净。
- 落地必做：把 `~/.hyperlpr3/<版本>/onnx/` 三个模型一次性拷入项目 `plate_models/`，
  改 `settings.py` 指向项目路径，验证断网可跑；封装为 `PlateRecognizer.detect_and_read(img) → List[PlateResult]`。
- 风险控制：用项目现有车辆素材（如 `tests/data/pic/远角车+人1.png`、`traffic.MP4`）实测
  **远角小车牌**与**新能源 8 位牌**；不行则「裁车 + 放大」后再送识别。

**第二步（精度/可迭代）：自训练检测 + 识别**

- 复用 ultralytics YOLO 训练**车牌检测器**（数据 CCPD / CBLPRD-330k），识别段用 CRNN/LPRNet；
  全链路自有权重、许可无忧，可与现有车辆检测合并或串联。
- 面向警用场景补充警用/武警/双层样本，逐步替换 HyperLPR3。

**不建议**：直接嵌入 GPL-3.0（we0091234）或 AGPL-3.0（openalpr）到交付产品；无许可项目
（zhubenfu、light-LPR）一律不可用。

**集成草图（确认后按「文档先行」推进）**：

```
umvp/plate_recog/plate_recognizer.py    # PlateRecognizer：detect_and_read(img) → List[PlateResult]
                                        # PlateResult{plate_no, plate_type, color, score, bbox}
plate_models/                           # 自包含车牌模型（视方案确定）
web_lab/server.py                       # PARAMS + h_plate_recog（测试台选图实测）
doc/modules/车牌识别.md                  # 参数/输入/输出分册
链路                                    # YOLO 识车 → 裁车放大 → 车牌识别 →（去重/告警）
```

## 七、数据集与自训练路线

- **CCPD**（MIT，ECCV 2018，30 万+）：中文车牌检测/识别基准，含 Base/DB/Blur/FN/Rotate/Tilt/Challenge
  子集；另有 **CCPD-Green**（新能源 8 位牌）。标注内嵌于文件名（省份/字母/数字索引）。
- **CBLPRD-330k**（MIT，33 万）：更均衡的中文车牌数据集，适合训练。
- **UFPR-ALPR / RodoSol-ALPR**：巴西/多国数据集，含标注，适合通用模型。
- **车牌生成器**（`Pengfei8324`、`ufownl/fake_chs_lp`、`yuto3o` 等）：合成中文车牌，做数据增强/预训练。
- 训练参考实现：`we0091234/crnn_plate_recognition`、`sirius-ai/LPRNet_Pytorch`、`qjadud1994/CRNN-Keras`。

## 八、待验证清单

在选定方案后，用项目现有素材做原型实测（约 10 分钟）：

```bash
# 1. 安装（在 conda 环境 ai 下）
conda run -n ai pip install hyperlpr3

# 2. 用项目现有车辆素材实测精度/耗时（远角、小车牌是重点）
conda run -n ai python -c "
import cv2, hyperlpr3 as lpr3
catcher = lpr3.LicensePlateCatcher()
img = cv2.imread('tests/data/pic/远角车+人1.png')
print(catcher(img))"
```

重点确认三件事：

1. **远角小车牌**能否读出（不行则先裁车放大，复用 CropRestore 的 upscale 思路）；
2. **模型文件位置**能否搬进项目 `plate_models/` 并改配置（自包含）；
3. **断网**能否运行（离线部署前提）。

> 注：以上为方案验证命令，尚未在 UMVP 环境实测；实测后建议将结论回写本文档并落地设计文档。
