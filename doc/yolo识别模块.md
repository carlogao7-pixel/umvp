# YOLO 识别模块（YOLODetector）参数与输出说明

> 适用范围：`umvp/pipe/composer.py` 中的 `YOLODetector` 模块。
> 模块职责一句话：**推理（可选）→ 过滤 → 按识别类型（类别）报送**。
> 本文列出该模块的全部可配置参数、输出字段，每条给出技术上的具体描述和通俗描述。

---

## 一、模块定位

YOLO 识别模块是分析管道中"**小模型识别**"这一环，承担三件事：

1. **推理**：用 YOLO 权重对一帧图像做目标检测（可关，见 `model_path`）。
2. **过滤**：按一套可自定义顺序的规则，把不合格的目标从结果里剔掉。
3. **报送**：把画面里"值得送审"的目标整理成请求，交给下一环（VLM 大模型研判或告警策略）。报送粒度固定为**按识别类型（类别）**——画面里每出现一类识别对象（且数量在配置的范围内）就发一条请求，同一类的多个目标合并成一条。

它在四种分析模式（small_only / small_crop / small_full / large_only）中负责 small 部分；模式差异全部收敛为参数配置，代码本身不写分支。

## 二、可配置参数

### 2.1 推理参数（ultralytics 底层透传）

| 参数 | 默认值 | 具体描述 | 通俗描述 |
|---|---|---|---|
| `model_path` | `None` | YOLO 权重路径（`.pt` 文件）。**为空时模块退化为纯后处理**：不加载模型、不可推理，只做过滤和报送（供外部已跑好检测列表的场景复用）。 | 决定用哪个"眼睛"模型。不填的话，这个模块就不自己看图，只负责整理别人给它的结果。 |
| `conf` | `0.35` | 检出置信度阈值。低于该分数的检测框会被模型丢弃。调低可召回被遮挡/重叠/小目标，但会引入更多误检。 | "自信程度"门槛。0.35 表示模型至少要有 35% 把握才认这个目标；门槛越低，认出的越多、但误认的也越多。 |
| `iou` | `0.7` | NMS（非极大值抑制）阈值。用于合并同一目标的重复框。调低允许高度重叠的框并存（多个目标叠在一起时保留更多框）。 | 两个框重叠得多厉害算"同一个目标"。0.7 意味着重叠超 70% 的框会被合并成一个；调低后，重叠的目标更可能被拆开分别保留。 |
| `imgsz` | `640` | 推理分辨率（单边像素）。输入会缩放/填充到该尺寸再推理。调高可召回小目标、重叠目标；**算力代价约随分辨率平方增长**。 | 喂给模型看的图多大。图越大看得越细、越容易发现小东西，但也越费算力。640→960 大约要花一倍多的计算量。 |
| `max_det` | `300` | 单帧最多返回的目标数上限。 | 一帧画面最多认几个目标。防止画面特别拥挤时结果列表过长。 |
| `classes` | `None` | 只检出这些类别（COCO 类别编号列表），`None` 表示不限制。例：`[0, 2]` 只认人(person=0)和车(car=2)。 | 限定"只关心哪些东西"。比如只想识别人和车，就只填这两类，其余一律不认。 |
| `device` | `None` | 推理设备：`"0"` 用 GPU 0 号、`"cpu"` 用 CPU、`None` 交给 ultralytics 自动选择。 | 让模型在哪张"显卡/脑子"上算。不填就自动挑。 |

> 推理参数在任务配置（spec）里对应 `yolo_model` / `yolo_conf` / `yolo_iou` / `yolo_imgsz` / `yolo_max_det` / `yolo_classes` / `yolo_device` 这些键，未显式配置的字段保持默认值、不参与拼接。

### 2.2 过滤与报送参数（模块自身逻辑）

| 参数 | 默认值 | 具体描述 | 通俗描述 |
|---|---|---|---|
| `filters` | `[]` | 可自定义顺序的过滤链，元素是 `Filter` 谓词（对单个 Detection 返回 True/False），逐个作用于检测列表。**顺序可自定义**（过滤规则集合语义，不同顺序结果一致）。 | 一组"筛子"，按你排的顺序把目标逐个过滤。不满足条件的直接剔除，不进入报送。 |
| `class_limits` | `{}` | 识别对象白名单：`类别编号 -> (数量下限, 数量上限)`。未登记的类别直接忽略；**数量按过滤链后的该类目标数**计算，不在 `[下限, 上限]` 范围内则整个类别不报送。 | "关注清单"。登记哪几类才报哪几类；每类还限了"几个才算数"——太少不算数，太多（比如人群聚集超上限）也不报这一类。 |
| `check_interval` | `3.0` | 每类独立计时的送审节拍（秒）。同一类别距上次报送不足该秒数则跳过；**一类目标再多也只算一条请求**。各类别计时互不影响。 | 同类目标多久"复查"一次。比如 3 秒：同一类目标 3 秒内最多送一次审，避免反复打扰。 |
| `roi` | `False` | 报送素材形式开关：`False` 送全帧（引用 `full:cls{类别}`，由拼接层画该类框标注）；`True` 送该类目标包围区域的裁剪图（引用 `crop:cls{类别}`）。 | 报上去给大模型看的"料"是什么——整张画面，还是只裁这一类的目标局部图。 |

### 2.3 内置过滤器（filters 可用的现成筛子）

| 过滤器 | 参数 | 具体描述 | 通俗描述 |
|---|---|---|---|
| `filter_model(path)` | 模型文件名 | 只保留 `model_path` 为该文件名（或未标记来源）的目标。 | 只认"指定这台模型认出来的目标"，其它模型出的结果丢弃。 |
| `filter_confidence(t)` | 分数阈值 | 只保留 `score >= t` 的目标。 | 只留"把握至少 t"的目标，够稳的才要。 |
| `filter_classes(cs)` | 类别编号列表 | 只保留 `cls_id` 在 `cs` 中的目标。 | 只留清单里的那几类东西。 |
| `filter_min_size(min_short, min_long)` | 短边、长边像素 | 只保留 `min(宽,高) >= min_short` 且 `max(宽,高) >= min_long` 的目标。 | 目标在画面里至少要多大的框才认——太小的（远处）不要。 |

## 三、输出字段

### 3.1 推理/过滤输出：`Detection`（单条目标）

| 字段 | 类型 | 具体描述 | 通俗描述 |
|---|---|---|---|
| `track_id` | `int` | 跟踪编号。`infer(track=True)`（BOTSORT）时跨帧稳定；无跟踪时为 0。 | 这个目标的"身份证号"。同一目标在前后几帧里编号不变，用于驻留（停留）统计。 |
| `cls_id` | `int` | 类别编号（COCO 编号，如 person=0、car=2）。 | 认出来是"哪类东西"的编号。 |
| `bbox` | `(x1, y1, x2, y2)` | 目标包围框，像素坐标（左上、右下）。 | 目标在画面里的位置和大小——左上角和右下角的两个点。 |
| `score` | `float` | 模型置信度（0~1）。 | 模型对"这就是这类东西"的把握程度。 |
| `model_path` | `str` | 产出该目标的权重文件名（仅文件名，不含路径）。 | 这条结果是哪台模型认出来的。多模型组合时用来区分来源。 |

### 3.2 报送输出：`SubmitRequest`（YOLO → VLM / 告警的请求，由 `process()` 产出）

| 字段 | 类型 | 具体描述 | 通俗描述 |
|---|---|---|---|
| `track_key` | `int` | 报送粒度标识：按类报送时为类别编号；`scene` 整帧报送时为 -1。 | 这条请求是关于"哪一类"（或整帧）的。 |
| `gran` | `str` | 报送粒度：`"class"`（按识别类型）/ `"scene"`（周期性整帧）。 | 这次报的是"一类目标"还是"整幅画面"。 |
| `ref` | `str` | 素材引用：`full:cls{类别}`（送全帧）/ `crop:cls{类别}`（送该类裁剪）/ `full:global`（整帧，large_only）。 | 下游该去哪取素材、怎么取——整帧还是裁剪图。 |
| `det` | `Detection` | 单目标素材保留字段（当前按类报送时为空）。 | 预留的单目标模式字段，现在不用。 |
| `dets` | `List[Detection]` | 该类别全部有效检测（`scene` 整帧报送时为空）。 | 这条请求里包含的该类所有目标明细。 |

## 四、参数调整速查（通俗指南）

- **漏检了重叠/遮挡目标** → 降 `conf`、降 `iou`、提 `imgsz`（按此顺序先温和后激进，参考 `tests/test_yolo_params.py` 的对比参数组）。
- **误检太多** → 升 `conf`（严格一点）、必要时用 `filter_min_size` 剔掉过小目标。
- **画面里目标太多、报送负担大** → 提 `check_interval` 拉长复查间隔；或调 `class_limits` 上限把"过度拥挤"的类整体跳过。
- **只想关注部分类别** → `classes` 限定推理类别（省算力），`class_limits` 限定报送白名单。
- **想看小图还是全图** → `roi`：`True` 送裁剪（省大模型流量、聚焦局部）；`False` 送全帧（保留上下文，拼接层画框标注）。

---

## 五、注意事项

- `model_path` 为空时模块为**纯后处理**模式：只过滤+报送，`infer()` 会抛错。
- 报送粒度**按类不按目标**：同一类多个目标合并为一条请求；驻留告警（dwell）仍按 track 记首次出现，但那是告警策略内部逻辑，不产生报送请求。
- 未在 `class_limits` 登记的类别即使检出也不报送。
- 推理参数全部透传 ultralytics：`imgsz` 影响算力约为平方关系，调参时留意 CPU 性能基线（YOLO 单帧约 1.7s，首载后更低）。
