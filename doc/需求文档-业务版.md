# 视觉识别链路定制系统 —— 需求文档（业务版）

> 面向使用者：通俗说明，不贴代码。配套技术文档见《需求文档-开发版》。

## 一、我们为什么要做这件事

现在项目里已经有了一批**搭好的积木**：

- 管道四模块：抽帧 → 小模型识别 → 大模型研判 → 告警策略
- 人脸识别三件套：检测 → 提取特征 → 底库检索
- 视频扫描、抽帧调度、原分辨率人脸提取

每块积木都能单独跑、单独调参，也已经有一个网页测试台可以逐个试。

但还缺三样东西，缺了它们，这套系统只能"自己玩"，不能"给别人用"：

1. **一本使用手册**（skill 文档）：告诉"干活的人"（可以是 AI 助手）每块积木怎么拼、什么场景用什么拼法、拼完怎么验证。
2. **一个干活的助手**（AI agent）：你说需求（比如"单卡 8G 显存，16 路摄像头实时识别行人"，它就帮你设计链路、估算资源、生成测试、跑通验证。
3. **一个定制台**（网页服务）：像搭积木一样在网页上选模块、连链路、填参数，当场看到这个链路要占多少显存/内存、每秒能处理多少帧。

另外，所有积木拼成完整链路后，**占多少显卡/内存、跑多快**，目前只能靠经验拍脑袋。用户觉得缺的正是这个：**完整链路的 GPU/内存占用自动估算**。

## 二、我们要做四件事

### 1. 资源估算（核心新能力）
- 知道"每块积木"吃多少：显存、内存、单帧耗时，分 CPU 和 GPU 两种情况。
- 知道"整条链路"吃多少：把各块积木加起来，算出一路、以及多路并发（比如 16 路摄像头）的总占用。
- 反过来算：给你一个资源上限（比如"只能用 8G 显存"），自动建议该隔几帧抽一次、多久报一次，让链路刚好装得下。
- 估算有两种方式：快算（不加载模型，按经验公式估，秒出）和实测（真跑一遍测出来，存下来下次直接用）。

### 2. 链路定制网页服务
在现有测试台基础上增加一个"链路设计器"视图：
- 网页上选模块、选顺序、填参数，组成一条完整链路。
- 页面上直接显示这条链路的资源估算结果（显存/内存/吞吐）。
- 一键"生成"：把这条链路转成可运行的配置和测试脚本。
- 一键"运行测试"：当场跑一遍，看结果。
- 同一个服务入口，不另装新东西。

### 3. AI 助手（agent）
- 你说人话描述需求，它给出链路方案。
- 方案包含：用哪些模块、什么顺序、什么参数、预计占多少资源。
- 它能自己生成测试代码、跑通验证，并把结果汇报给你。
- 它的"业务知识"来自第 1 件里的使用手册（skill 文档）。

### 4. 完善使用手册（skill 文档）
把现在只有"人脸提取"一条的记录，扩成覆盖全部链路的手册：
- 每块积木的能力、参数、资源占用。
- 什么场景用哪种链路（决策表）。
- 拼装套路和验证方法。
- 常见的坑（以前踩过的都记下来）。

## 三、谁会用、怎么用

| 使用者 | 用途 | 例子 |
|---|---|---|
| 算法/部署工程师 | 搭新链路前先估资源 | "这条链路 16 路并发要多少显存？" |
| 项目负责人 | 决策用 | "单卡能不能同时跑人脸库检索和车辆识别？" |
| AI 助手 | 自主规划 | "按 8G 显存约束，帮我设计并验证一条巡检链路" |

## 四、分几步做（里程碑）

| 阶段 | 内容 | 做完能干什么 |
|---|---|---|
| 第一步（基础） | 资源估算模块 + 测试台里每模块显示资源指纹 | 网页上每个模块都告诉你它吃多少 |
| 第二步（链路） | 链路设计器 + 整链路估算 + 多路推演 + 生成脚本 | 网页上搭一条链路，看到总占用，一键生成可跑脚本 |
| 第三步（智能） | 完善 skill 手册 + 建立 agent | AI 助手能按需求设计链路、估算、生成、测试 |

## 五、验收标准（怎么算做完）

1. **资源估算**：对每个模块，能给出 CPU 和 GPU 下的单帧耗时、显存、内存，误差在可接受范围（实测验证）；多路并发能线性外推并给出提示。
2. **反推**：给定资源上限，能建议抽帧间隔等参数，使链路总占用不超限。
3. **链路设计器**：网页上能拼出一条完整链路，显示估算结果，一键生成配置和测试脚本，一键运行。
4. **AI 助手**：用自然语言描述一个需求，它能给出含资源估算的链路方案，并自动生成测试跑通。
5. **手册**：skill 文档覆盖全部模块与四种分析模式，新助手读后能独立工作。
6. **不破坏现有**：之前所有已验证的模块测试（27 项断言、人脸 7/7 自检、三模式实机）仍然全部通过。

## 六、边界与说明

- 资源估算以本机（RTX 3060 + CPU）为基准环境，换机器需重新实测标定；公式法只做粗估。
- 估算值用于"方案决策"，不替代真机压力测试。
- 视频扫描等重型测试仍按现有"限帧数"约定，避免一次跑太久。
- 大模型研判（VLM）的耗时取决于远端端点，估算按"发送请求 + 等待返回"建模，实际以实测为准。

## A1. 帧调度

### A1.1 抽帧调度 FrameScheduler
根据积压队列或推理耗时，自动放宽/收紧抽帧间隔，防止处理不过来。
| 参数 | 说明（默认值） |
|---|---|
| 模式 | queue=按积压信号放宽；adaptive=按推理耗时自动放宽（queue） |
| 模拟场景 | 平稳 / 积压浪涌 / 耗时渐增，用于模拟不同压力（平稳） |
| 基础抽帧间隔 | 默认每几帧取一张；积压时自动加大（3 帧） |
| 积压阈值 | 积压超过它就开始放宽抽帧（32） |
| 放宽倍数 | 放宽时抽帧间隔乘以几倍（2） |
| 放宽上限 | 间隔最多放宽到多少；0=不限（0） |
| 放宽比例 | 自适应模式：耗时变长时间隔乘多少（1.2） |
| 恢复比例 | 自适应模式：耗时恢复后间隔按什么比例回落（0.5） |
| 视频帧率 | 用于估算每帧推理时间预算（25） |
| 模拟帧数 | 模拟多少帧的调度过程（30） |

## A2. 管道四模块

### A2.1 帧管理 FrameManager
三种取图节奏的决策器，决定哪些帧被取走送检。
| 参数 | 说明（默认值） |
|---|---|
| 取图节奏 | analysis=随抽帧节奏；wall_clock=按墙钟秒；frame_count=按帧数（analysis） |
| 抽帧间隔 | 每 N 帧取一张（analysis 模式用）（3 帧） |
| 墙钟间隔 | 每隔多少秒取一张（wall_clock 模式用）（3 秒） |
| 帧数间隔 | 每隔多少帧取一张（frame_count 模式用）（30 帧） |
| 模拟帧数 | 模拟播放多少帧，观察逐帧取/跳决策（20） |
| 每帧时间步长 | 模拟时间轴：相邻两帧相差几秒（1 秒） |

### A2.2 小模型识别 YOLODetector
用 YOLO 小模型检出目标，按类别过滤、去重、报送。
| 参数 | 说明（默认值） |
|---|---|
| 权重模型 | 检测权重；不选则用默认 yolov8n.pt（下拉选择） |
| 测试图片 | 要检测的图片（下拉选择） |
| 检出阈值 conf | 置信度低于它的框被丢弃；调高更严格（0.35） |
| NMS 阈值 iou | 重叠超过它的重复框合并成一个（0.7） |
| 推理分辨率 imgsz | 送进模型的分辨率；越大越慢，小目标更清楚（640） |
| 单帧最多目标 | 一帧最多保留多少个目标（300） |
| 类别白名单 | 只识别这些类别，逗号分隔，空=不限；COCO: 0=人, 2=车（0） |
| 推理设备 | 如 cpu 或 0；空=自动（空） |
| 过滤链：置信度下限 | 低于它的检出直接丢弃（0=不启用）（0） |
| 过滤链：短边最小像素 | 目标短边小于它不报送（0=不启用）（0） |
| 过滤链：长边最小像素 | 目标长边小于它不报送（0=不启用）（0） |
| 每类数量上下限 | 类别:下限,上限，分号分隔；空=不报送（0:1,300） |
| 报送节拍 | 同一类别每隔几秒报一次，避免刷屏（3 秒） |
| 裁剪送审 | 开=送该类裁剪图；关=送全帧（关） |
| 报送时间戳 | 本帧时间戳，随报送结果带出（0 秒） |

### A2.3 大模型研判 VLMAnalyzer

## A4. 视频监控

### A4.1 视频扫描 FaceMonitor
抽帧 + 人脸检测 + 嵌入 + 底库检索全链路，扫视频找出底库中人。
| 参数 | 说明（默认值） |
|---|---|
| 测试视频 | 要扫描的视频文件（下拉选择） |
| 底库文件 | 拿视频里的人脸去比对的底库（out/face_db.npz） |
| 设备 | auto=自动；cuda=显卡；cpu=CPU（auto） |
| 抽帧间隔 | 每隔几帧检测一次（3 帧） |
| 积压阈值 | 积压超过它放宽抽帧（32） |
