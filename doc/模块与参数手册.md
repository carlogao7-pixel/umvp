# 模块与参数手册

> 本文档是「模块及参数、配置、输入输出」的独立手册，列出 web_lab 测试台全部 12 个模块。
> 权威源：`web_lab/server.py`（PARAMS 参数清单 / MODULES 注册表 / h_* 处理器）、`umvp/pipe/composer.py`（四模块实现）。
> 配套文档：端口与启停 → `doc/端口与启停手册.md`；数据库结构 → `doc/数据库结构.md`；
> 通俗总览 → `web_lab/设计说明.md`。

## 2. 通用约定

- **参数类型**：`int` / `float` / `str` / `text`（多行）/ `bool`（勾选）/ `select`（下拉）。
- **file 参数**：从项目内置目录下拉选择，按 `src` 分三类——`model`（`models/*.pt`）、
  `img`（测试图片目录）、`vid`（测试视频目录）。留空时多数回落到默认权重（yolov8n.pt）。
- **留空语义**：`str` 类参数留空=不启用/自动；数字类参数 `0` 常见含义为「关闭」或「不限」，见各表说明。
- **报送（submit）**：小模型/大模型的结论以 `SubmitRequest` 形式带时间戳上报，告警模块据此判定。
- **命名配置**：每个模块的参数可「保存命名配置」入 MySQL，再按名字载回复用；与链路阶段参数是同一份数据。
- **资源估算**：模块测试页顶部有资源估算区，链路设计器可对整链估算（见 `umvp/resources.py`）。

## 3. 管道四模块（umvp/pipe/composer.py）

### 3.1 frame_manager（帧管理 FrameManager，含原 frame_scheduler）

复用 `pipe.composer.FrameManager`。取帧节奏决策 + 背压自动放宽：给定每帧序号/时间戳回答
「这一帧取不取」；积压队列或推理耗时超过预算时自动放宽抽帧间隔（原 `face_scan` 抽帧调度
并入，2026-08-18）。

| 参数名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| sampling | select | analysis | 取图节奏：analysis=随抽帧节奏; wall_clock=按墙钟秒; frame_count=按帧数 |
| frame_skip | int | 3 | 每 N 帧取一张（analysis 模式用）；积压/耗时超预算时自动加大 |
| interval_sec | float | 3.0 | 每隔多少秒取一张（wall_clock 模式用） |
| interval_frames | int | 30 | 每隔多少帧取一张（frame_count 模式用） |
| mode | select | queue | 背压判定：queue=按积压队列信号放宽; adaptive=按推理耗时自动放宽 |
| scenario | select | 平稳 | queue 用「积压浪涌」造高峰；adaptive 用「耗时渐增」 |
| queue_threshold | int | 32 | 积压超过它就开始放宽抽帧 |
| backpressure_multiplier | int | 2 | 放宽时抽帧间隔乘以几倍 |
| max_frame_skip | int | 0 | 抽帧间隔最多放宽到多少；0=不限 |
| adaptive_relax_ratio | float | 1.2 | 耗时变长时，间隔乘多少 |
| adaptive_recover_ratio | float | 0.5 | 耗时恢复后，间隔按什么比例回落 |
| fps | float | 25.0 | 视频帧率，用来估算每帧推理时间预算（adaptive 模式用） |
| n_frames | int | 30 | 模拟多少帧的调度过程 |
| ts_step | float | 1.0 | 模拟时间轴：相邻两帧相差几秒 |

- **输入**：以上参数（模拟帧序列 + 模拟背压/耗时曲线）。
- **输出**：逐帧「取/跳」决策表（帧号、时间戳、是否取图）、间隔变化序列 + 日志。

### 3.2 yolo（小模型识别 YOLODetector）

| 参数名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| model_path | file(model) | yolov8n.pt | 检测权重；不选则用默认 |
| image | file(img) | — | 要检测的测试图片 |
| conf | float | 0.35 | 检出阈值，置信度低于它的框丢弃；调高更严格 |
| iou | float | 0.7 | NMS 阈值，重叠超过它的重复框合并 |
| imgsz | int | 640 | 推理分辨率；越大越慢，小目标更清楚 |
| max_det | int | 300 | 单帧最多保留多少个目标 |
| classes | str | 0 | 类别白名单（逗号分隔，空=不限）；COCO: 0=人, 2=车 |
| device | str | （空） | 推理设备，如 cpu 或 0；空=自动 |
| filter_conf | float | 0.0 | 过滤链：置信度下限（0=不启用），低于它的检出不报送 |
| min_short | int | 0 | 过滤链：短边最小像素（0=不启用） |
| min_long | int | 0 | 过滤链：长边最小像素（0=不启用） |
| class_limits | str | 0:1,300 | 每类数量上下限，如 `0:1,300; 2:1,10`；空=不报送 |
| check_interval | float | 3.0 | 报送节拍（秒/类），同一类别每隔几秒才报一次 |
| roi | bool | False | 裁剪送审：开=送该类裁剪图; 关=送全帧 |
| ts | float | 0.0 | 报送时间戳（秒），随报送结果带出 |

- **输入**：测试图片 + YOLO 推理/过滤/报送参数。
- **输出**：标注图片（画框）、检出清单（框坐标/类别/置信度）、报送请求列表（SubmitRequest）。
- **链路协作**：链路段只传入推理参数（model_path/conf/…/classes），过滤链与报送参数
  （filter_conf/min_short/min_long/class_limits/check_interval/roi）由链路 spec 决定，
  `_chain_from_spec` 统一按固定顺序施加过滤链再按 class_limits 报送。

### 3.3 vlm（大模型研判 VLMAnalyzer）

| 参数名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| crop_padding | float | 0.15 | 裁剪目标时往外多扩多少，避免贴边 |
| max_resolution | str | 1280,720 | 送审图片最大尺寸（宽,高），超出会缩小 |
| prompt | text | （空） | 提示词；留空用默认分类提示词 |
| ref | select | crop:cls0 | 素材引用：crop:cls0=裁剪第 0 类目标送审; full:cls0=全帧按第 0 类; full:global=全帧全局 |
| gran | select | class | 报送粒度：class=按类别一次; scene=整场景一次 |
| track_key | int | 0 | 素材对应的目标类别编号（scene=-1） |
| bbox | str | 10,10,100,200 | 单目标 bbox（x1,y1,x2,y2），选裁剪送审时用 |
| det_count | int | 2 | 没填 bbox 时，用它代表该类目标数量 |
| use_real_vlm | bool | False | 勾选才真发请求；不勾只演示生成素材包 |
| vlm_endpoint | str | http://117.42.21.253:8000/v1/chat/completions | 大模型接口地址 |
| vlm_model | str | qwen3-vl-32b | 调用的模型名称 |
| vlm_key | str | （空） | API Key；免鉴权可留空 |

- **输入**：素材字段（裁剪/全帧引用、prompt、端点）。
- **输出**：素材包内容（JSON：引用的图、目标信息、待审问题）；勾选真实 VLM 时输出判定动作。
- **驱动依赖**：模块单测默认**不调真实端点**（演示返回固定结果），勾选 `use_real_vlm` 才发起真实请求。

### 3.4 alarm（告警策略 AlarmPolicy）

三种判定方式 + 冷却。**同时支持 YOLO 与 VLM 两类输入**（见下文「双入口」）。

| 参数名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| kind | select | window | 判定方式：window=VLM滑动窗口; dwell=驻留秒数; inspection=直接落盘 |
| task_id | int | 1 | 告警带上的任务编号 |
| target_actions | str | fire,fight | 哪些动作算告警（逗号分隔，空=巡检） |
| smooth_frames | int | 2 | 窗口长度 / 驻留秒数：window=连续几帧看; dwell=驻留几秒才报 |
| hit_ratio | float | 1.0 | 窗口内命中比例到多少才告警（1.0=全部命中） |
| alarm_cooldown | float | 60.0 | 同一目标告警后多久内不再重复报 |
| timeline | text | （示例脚本） | 事件时间线（每行一条），格式见下 |

**时间线脚本格式**（`timeline`）：
- `kind=window/inspection`：每行 `ts, track_key, action`，例如 `1.0, 0, fire`。
- `kind=dwell`：每行 `ts, track_id, cls_id`，例如 `10.0, 1, 0`。

**双入口（告警怎么同时处理 YOLO 和 VLM 的输出）**：
| 入口 | 触发方 | 输入 | 用途 |
|---|---|---|---|
| `on_dwell(track_id, cls_id, ts)` | YOLO 路径，Pipeline.step() 内同步 | 驻留事件：track 首次出现时间 → 驻留秒数=ts-first_seen | dwell 判定（驻留告警） |
| `on_vlm_result(track_key, action, ts)` | VLM 路径，外部回调（Pipeline.on_vlm_result） | 动作判定事件：目标类别 key + 动作名 | window / inspection 判定（VLM 窗口确认告警） |

- 冷却作用域不同：dwell 按 `(task_id, cls_id)` 每类冷却；VLM 路径按 `(task_id, task_id)` 全局冷却。
- 报送粒度：`track_key=-1` 时按 scene（整场景），否则按 class（该目标类别）。
- **输入**：事件时间线脚本（或链路运行中由上游 YOLO/VLM 实时喂入事件）。
- **输出**：告警事件表（ts, gran, track_key, action）+ 日志。

### 3.5 compose（四模式集成 compose）

把四种分析模式的差异收敛为一份扁平配置，端到端跑通（`pipe/composer.compose(spec)`）。

| 参数名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| algo_mode | select | small_crop | 分析模式：small_only / small_crop / small_full / large_only |
| task_id | int | 1 | 告警与报送带上的任务编号 |
| feed | select | script | 驱动方式：script=脚本化检测输入; real=真实图片+YOLO 推理 |
| script | text | 示例 | 脚本（每行: 帧,秒,类别,数量[,起始track]） |
| image | file(img) | — | real 模式用的输入图片 |
| extract_frame_rate | int | 3 | 抽帧间隔（帧） |
| smooth_frames | int | 1 | 窗口长度 / 驻留秒数 |
| target_actions | str | fire,fight | 哪些动作算告警 |
| alarm_cooldown | float | 60.0 | 冷却（秒） |
| class_limits | str | 0:1,300 | 每类数量上下限 |
| check_interval | float | 3.0 | 报送节拍 / 墙钟间隔（秒） |
| roi_output | bool | False | 勾选=目标裁剪图送大模型；不勾=送全帧 |
| crop_padding | float | 0.15 | 裁剪外扩比例 |
| vlm_max_resolution | str | 1280,720 | 送大模型的图最大尺寸 |
| vlm_prompt | text | （空） | VLM 提示词，留空用默认 |
| vlm_hit_ratio | float | 1.0 | VLM 判定命中比例阈值 |
| yolo_model | file(model) | yolov8n.pt | YOLO 权重 |
| yolo_conf | float | 0.35 | YOLO 置信度阈值 |
| yolo_iou | float | 0.7 | YOLO 去重阈值 |
| yolo_imgsz | int | 640 | YOLO 推理分辨率 |
| yolo_max_det | int | 300 | YOLO 单帧最多目标数 |
| yolo_classes | str | 0 | YOLO 类别（空=不限） |
| yolo_device | str | （空） | YOLO 设备（空=自动） |
| vlm_feedback | bool | True | VLM 回填（把 action 喂回告警） |
| vlm_action | str | fire | 回填时使用的动作名 |

**四种模式 = 模块组合**（差异全在配置，不写分支代码）：

| 模式 | 帧管理 | YOLO | VLM | 告警 |
|---|---|---|---|---|
| small_only | analysis 抽帧 | 有 | 无 | dwell（驻留告警） |
| small_crop | analysis 抽帧 | 有（裁剪送审） | 有 | window |
| small_full | analysis 抽帧 | 有（全帧送审） | 有 | window |
| large_only | wall_clock 墙钟秒 | 无 | 有（全帧 global） | window |

- **输入**：四模式配置（扁平）。
- **输出**：每步报送/告警记录（逐帧日志 + 结果表）。
- **提示**：dwell 告警用脚本驱动时，同一起始 track 连续几行模拟驻留。

## 4. 人脸识别链路

### 4.1 face_detect（人脸检测 FaceDetector）

复用 `face_detect.face_detector`（SCRFD + 5 点对齐）。

| 参数名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| image | file(img) | — | 要检测的测试图片 |
| device | select | auto | auto=自动; cuda=显卡; cpu=CPU |
| det_thresh | float | 0.5 | 检测阈值，低于它的脸不认；调低检出更多（也更多误检） |
| det_size | str | 640,640 | 检测分辨率（宽,高），越高越慢，小脸更清楚 |
| max_num | int | 0 | 最多返回几张脸（0=不限） |
| use_crop | bool | True | 同时输出 5 点对齐后的脸部裁剪图 |

- **输入**：测试图片 + 检测参数。
- **输出**：标注图片、逐脸列表（框 + 5 点）、对齐裁剪图。

### 4.2 face_embed（特征提取 FaceEmbedder）

复用 `face_embed.face_embedder`（ArcFace，512 维）。

| 参数名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| image | file(img) | — | 测试图片（自动先检测再嵌入） |
| device | select | auto | auto=自动; cuda=显卡; cpu=CPU |
| det_thresh | float | 0.5 | 检测阈值 |
| det_size | str | 640,640 | 检测分辨率 |

- **输入**：测试图片（内部先 SCRFD 检脸，再对每张脸提取向量）。
- **输出**：每张脸 512 维向量概况（维数/样本数）。

### 4.3 face_store（向量底库 FaceStore）

复用 `face_embed.face_store`（numpy 线性检索）。

| 参数名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| action | select | register_dir | 操作：register_dir / register_single / query / self_check / list |
| db_path | str | out/face_db.npz | 底库存到哪；不存在会自动新建 |
| thresh | float | 0.45 | 检索阈值，相似度低于它不算命中（0~1，越大越严） |
| topk | int | 5 | 查询返回最像的前几个 |
| device | select | auto | auto=自动; cuda=显卡; cpu=CPU |
| register_dir | str | umvp/face_detect/test_imgs | 注册目录，每张图=一个身份，文件名即身份名 |
| image | file(img) | — | register_single / query 用的图片 |
| name | str | （空） | register_single 用的身份名 |

- **输入**：操作 + 底库参数（注册目录/单张图/查询图）。
- **输出**：注册记录、命中结果（身份+相似度）、底库统计（身份数/向量数）。

### 4.4 extract_faces（原分辨率提取 extract_faces）

复用 `pipe.crop_restore`：YOLO 识人 → 裁人 → SCRFD 检脸 → 坐标还原 → 原图出脸。

| 参数名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| image | file(img) | — | 含人的原图 |
| yolo_model | file(model) | yolov8n.pt | YOLO 权重 |
| yolo_conf | float | 0.35 | YOLO 置信度阈值 |
| yolo_iou | float | 0.7 | 重叠超过它的人框合并 |
| yolo_imgsz | int | 640 | YOLO 推理分辨率 |
| yolo_max_det | int | 300 | YOLO 单帧最多目标数 |
| yolo_classes | str | 0 | YOLO 识别哪类目标（0=人） |
| face_thresh | float | 0.4 | 人框内再找脸的人脸阈值 |
| upscale | float | 1.0 | 人框先放大几倍再找脸（1.0=原样） |
| margin | float | 0.15 | 输出人脸时往外多扩多少 |
| min_person_short | int | 30 | 人框长边小于它直接跳过 |
| dedup_iou | float | 0.6 | 两张脸重叠超过它算同一张，只留一张 |

- **输入**：含人原图 + YOLO/SCRFD 参数。
- **输出**：标注原图 + 每张**原生分辨率**人脸裁剪图。

## 5. 已完成链路（hidden 模块）

三个模块不在侧边栏分组中列出，作为「已完成链路」在侧边栏底部选名运行；运行表单由
`run_params`（默认参数）+ 链路 stages（阶段模块参数，可展开编辑）组成。

### 5.1 face_monitor（视频人脸检索 FaceMonitor）

| 参数名 | 类型 | 默认值 | 分组 | 说明 |
|---|---|---|---|---|
| video | file(vid) | — | 运行控制 | 要扫描的视频文件 |
| db_path | str | out/face_db.npz | 运行控制 | 拿视频里的人脸去比对的底库 |
| device | select | auto | 运行控制 | auto=自动; cuda=显卡; cpu=CPU |
| max_frames | int | 60 | 运行控制 | 限帧数（0=全部）；4K 长视频建议先限帧 |
| save_dir | str | tests/data/out/faces/monitor | 运行控制 | 命中帧图保存目录 |
| frame_skip | int | 3 | 帧管理 | 每隔几帧检测一次 |
| queue_threshold | int | 32 | 帧管理 | 积压超过它放宽抽帧 |
| backpressure_multiplier | int | 2 | 帧管理 | 放宽时抽帧间隔乘以几倍 |

- **输入**：视频 + 底库 + 抽帧参数。
- **输出**：扫描统计（分析帧数/检出人数/命中次数）、命中记录、命中帧标注图。
- **链路 seed**：名称「视频人脸检索」，stages = frame_manager + face_detect + face_embed + face_store。

### 5.2 frame_yolo（帧管理-YOLO识别链路）

参数分三组：运行控制 / 帧管理 FrameManager / YOLO 识别 YOLODetector。

| 参数名 | 类型 | 默认值 | 分组 | 说明 |

| interval_sec | float | 3.0 | 帧管理 | 每隔多少秒取一张（wall_clock 用） |
| interval_frames | int | 30 | 帧管理 | 每隔多少帧取一张（frame_count 用） |
| model_path | file(model) | yolov8n.pt | YOLO 识别 | 检测权重 |
| conf | float | 0.35 | YOLO 识别 | 检出阈值 |

### 5.3 chain（四模式链路 chain）

四模式链路的**通用运行器**：按 `spec.stages` 组装帧管理/YOLO/VLM/告警并逐帧驱动。
运行表单只含「驱动」参数，链路本体（各阶段模块参数）由已完成链路 spec 的 stages 提供。

| 参数名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| feed | select | script | 驱动方式：script=脚本化检测输入（模拟 YOLO 检出）; real=真实图片+YOLO 推理 |
| script | text | 示例 | 脚本（每行: 帧,秒,类别,数量[,起始track]） |
| image | file(img) | — | real 模式用的输入图片 |
| vlm_feedback | bool | True | VLM 回填（把 action 喂回告警） |
| vlm_action | str | fire | 回填时使用的动作名 |

- **输入**：链路 spec（algo_mode/runner/run_module/stages/run_params）+ feed 驱动。
- **输出**：每步报送/告警记录（逐帧日志 + 结果表）。

## 6. 链路拼接配置（runner=chain 详解）

2026-08-17 起，3 条四模式链路（small_only / small_yolo_vlm / large_only）**不再由服务器
播种**（代码与 SQL 中的种子已删除，模式概念统一改为"链路拼接"方式重建，替代链路待后续
任务生成）。`runner=chain` 运行器与 `_ALGO_EXPECT` 校验表保留，按下列 spec 结构手工拼接
的链路仍可运行（spec 带 `algo_mode` 顶层键时运行前校验 stages 与模式一致）：

```jsonc
{
  "algo_mode": "small_only",        // compose() 分派键，运行前按 stages 校验（可选）
  "runner": "chain",                // 运行入口：复用 /api/test/chain 处理器
  "run_module": "chain",            // 运行表单参数 schema 来源模块
  "name": "示例链路",
  "description": "...",
  "streams": 1,
  "stages": [                        // 阶段模块参数（网页上可按阶段展开编辑）
    {"module": "frame_manager", "params": {...}},
    {"module": "yolo", "params": {...}},
    {"module": "alarm", "params": {...}}
  ],
  "run_params": {                    // 运行表单默认值
    "feed": "script",
    "script": "0,0.0,0,2\n3,1.0,0,1\n6,3.0,0,1",
    "vlm_feedback": true, "vlm_action": "fire"
  }
}
```

链路必须包含 `frame_manager` 与 `alarm` 两个必需阶段；旧三条模式的阶段组合（重建时可参考）：

| 原模式 | 阶段（module → 关键参数） |
|---|---|
| small_only 小模型驻留告警 | frame_manager(analysis, frame_skip=3) → yolo → alarm(dwell, smooth_frames=2, target_actions=空) |
| small_yolo_vlm 小模型+大模型研判 | frame_manager(analysis, frame_skip=3) → yolo → vlm → alarm(window, smooth_frames=1, target_actions=fire,fight) |
| large_only 纯大模型研判 | frame_manager(wall_clock, interval_sec=3.0) → vlm → alarm(window) |

**与 compose 四模式的对应**：方案 A 把 small_crop / small_full 合并为 small_yolo_vlm
（ROI 裁剪/全帧不区分，`roi=false` 统一送全帧）；large_only 与 small_only 一一对应。

**运行语义注意**：
- dwell 告警（small_only）依赖「同一起始 track 的连续事件」；脚本驱动时用
  `0,0.0,0,2` 起 track、后续行同 track 续驻留。real 驱动为单帧单图，不会触发驻留。
- window 告警（small_yolo_vlm / large_only）依赖 VLM 动作回填，`vlm_feedback` 开启时
  回填的 action 喂给告警模块判定。
