# UMVP 数据库结构说明

> 本文档描述 web_lab 命名配置暂存（presets）所用 MySQL 库的当前结构，
> 与代码同步更新。数据依据：2026-08-07 对运行中实例的 `SHOW CREATE TABLE` 实测。

## 1. 概览

- **用途**：web_lab 前端"命名配置暂存/取用"的后端存储，把各模块/链路的命名配置
  （preset）存下来，供以后按名字取回复用。
- **数据库名**：`umvp`（默认，可用 `MYSQL_DB` 覆盖）
- **表数量**：3 张主表（`presets` / `pipelines` / `pipeline_steps`）+ 每模块一张参数表
  `preset_params_<module_id>`（当前注册 11 个模块 → 11 张参数表，见 §3.5）
- **引擎/字符集**：InnoDB / utf8mb4 / utf8mb4_unicode_ci
- **访问层**：`web_lab/db.py`（惰性连接，pymysql），HTTP 接口在 `web_lab/server.py`

## 2. 运行实例信息

| 项 | 值 | 覆盖方式 |
|---|---|---|
| 主机 | 127.0.0.1 | `MYSQL_HOST` |
| 端口 | 3307 | `MYSQL_PORT` |
| 用户 | umvp | `MYSQL_USER` |
| 密码 | 123 | `MYSQL_PASSWORD` |
| 数据库 | umvp | `MYSQL_DB` |

实例自含于项目内（免 sudo 启动）：

```bash
mysqld --datadir=项目/.mysql/data --socket=项目/.mysql/mysql.sock \
       --port=3307 --bind-address=127.0.0.1 --log-error=项目/.mysql/mysql.log
```

MySQL 不可用时不影响 web_lab 启动：`--no-db` 可显式禁用，presets 接口统一返回"未启用"。

### 2.1 运维命令（状态 / 开启 / 关闭）

```bash
# ---- 查看状态 ----
mysqladmin --socket=项目/.mysql/mysql.sock -u root ping   # 输出 mysqld is alive 即正常
ss -ltn | grep 3307                                       # 端口是否在监听
mysql --socket=项目/.mysql/mysql.sock -u umvp -p123 umvp \
  -e "SHOW TABLES; SELECT id,kind,name FROM presets;"     # 看库内容（应用账号）
tail -n 30 项目/.mysql/mysql.log                          # 排错看错误日志

# ---- 开启 ----
# 方式一：起 web_lab 时自动拉起（run.sh 检测 socket 不存在则自行启动，无需手动管）
./web_lab/run.sh --port 8001
# 方式二：单独手动启动
mysqld --datadir=项目/.mysql/data --socket=项目/.mysql/mysql.sock \
       --port=3307 --bind-address=127.0.0.1 \
       --log-error=项目/.mysql/mysql.log --daemonize

# ---- 关闭 ----
# umvp 应用账号没有 SHUTDOWN 权限，必须用 root 走 socket
mysqladmin --socket=项目/.mysql/mysql.sock -u root shutdown
```

注意两点：

- `--log-error` 必须指到项目内（默认 `/var/log/mysql/` 普通用户写不了，会导致启动失败）。
- 关库不影响 web_lab 启动，只是 presets 界面显示"数据库不可用"；`./web_lab/run.sh --no-db` 可显式禁用数据库。
数据库故障只影响暂存功能，不影响测试/校准等其它能力。

## 3. 表：`presets`（命名配置）

### 3.1 建表语句（实测）

```sql
CREATE TABLE `presets` (
  `id` int NOT NULL AUTO_INCREMENT,
  `kind` enum('module','pipeline') COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT 'module',
  `name` varchar(64) COLLATE utf8mb4_unicode_ci NOT NULL,
  `module_id` varchar(32) COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT '',
  `params_json` text COLLATE utf8mb4_unicode_ci NOT NULL,
  `created_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_kind_name` (`kind`,`name`)
) ENGINE=InnoDB AUTO_INCREMENT=34 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
```

### 3.2 字段说明（通俗版）

| 字段 | 含义 | 说明 |
|---|---|---|
| id | 自增主键 | 每次保存/覆盖递增，`load`/`delete` 按它定位 |
| kind | 配置类型 | `module`＝单模块配置；`pipeline`＝完整链路配置。仅允许这两个值 |
| name | 配置名 | 同 kind 下必须唯一；重复保存＝覆盖旧配置，不新建 |
| module_id | 模块标识 | 仅 `module` 类型用（如 `yolo`、`frame_manager`）；`pipeline` 类型恒为空串 |
| params_json | 配置内容 | 仅 `pipeline` 类型用（整条链路 spec JSON）；`module` 类型迁移后恒为空串，参数改存模块参数表（§3.5） |
| created_at | 创建时间 | 入库时自动记录 |
| updated_at | 最近更新时间 | 覆盖时自动更新；列表按它倒序排（最近用的在前） |

### 3.3 索引

| 索引 | 列 | 类型 | 作用 |
|---|---|---|---|
| PRIMARY | id | 主键 | 按 id 精确取用/删除 |
| uk_kind_name | kind, name | 唯一索引 | 保证"同 kind 下名字唯一"，并支撑同名覆盖判断 |

### 3.4 当前数据快照

- 行数：**1**（`id=12`，`kind=module`，名 `default1`，历史测试已清理）
- AUTO_INCREMENT=34：历史上有过 33 次插入（已删除的未回退），下次新建 id=34
- 该行的 `params_json` 已迁移置空，参数落在 `preset_params_frame_manager`（见 §3.5）

### 3.5 每模块一张参数表（`preset_params_<module_id>`，列式存储）

模块参数**不再整份塞进 `params_json`**，而是按模块拆成一张参数表，每参数一列、类型化存储。
设计细节见 `doc/配置参数列式化存储设计.md`，这里只记结构事实。

- 表名：`preset_params_<module_id>`，主键 `preset_id` 引用 `presets.id`，外键级联删除
  （删 presets 行时参数自动清理）。
- 列：每个参数一列，类型由 server.py 参数类型映射（int→INT / float→DOUBLE / bool→TINYINT(1) /
  select→VARCHAR(64) / file→VARCHAR(255) / str→VARCHAR(255) / text→TEXT）。
- 当前注册 11 张：alarm / compose / extract_faces / face_detect / face_embed / face_monitor /
  face_store / frame_manager / frame_scheduler / vlm / yolo。
- 表与列由 `init_db()` 按 `configure_modules()` 注册的 schema 自动建/补（加参数自动补列，
  删参数不删列），无需手工 DDL。

实测示例（`preset_params_yolo`，节选）：

```sql
CREATE TABLE `preset_params_yolo` (
  `preset_id` int NOT NULL,
  `conf` double DEFAULT NULL,
  `iou` double DEFAULT NULL,
  `imgsz` int DEFAULT NULL,
  `roi` tinyint(1) DEFAULT NULL,
  `model_path` varchar(255) DEFAULT NULL,
  `note` text,
  ...
  PRIMARY KEY (`preset_id`),
  CONSTRAINT `fk_pp_yolo` FOREIGN KEY (`preset_id`) REFERENCES `presets` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
```

当前行数：仅 `preset_params_frame_manager` 1 行（对应 default1），其余模块表为空。

## 4. 表：`pipelines`（链路拼装）

链路 = 一组**有序**模块步骤，每步引用一个已入库的模块 preset（`presets.id`，`kind='module'`）。
"只记 id + 顺序"之外的补充决策（链路级字段、角色从 preset 反查、引用完整性）见
`doc/链路拼装存储设计.md`。

### 4.1 建表语句（实测）

```sql
CREATE TABLE `pipelines` (
  `id` int NOT NULL AUTO_INCREMENT,
  `name` varchar(64) COLLATE utf8mb4_unicode_ci NOT NULL,
  `streams` int NOT NULL DEFAULT '1',
  `budget_json` text COLLATE utf8mb4_unicode_ci NOT NULL,
  `meta_json` text COLLATE utf8mb4_unicode_ci NOT NULL,
  `created_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_name` (`name`)
) ENGINE=InnoDB AUTO_INCREMENT=10 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
```

### 4.2 字段说明（通俗版）

| 字段 | 含义 | 说明 |
|---|---|---|
| id | 自增主键 | save/load/delete 按它定位 |
| name | 链路名 | 必须唯一；重复保存＝覆盖旧链路（id 不变、步骤重建），不新建 |
| streams | 路数 | 多路外推，默认 1 |
| budget_json | 资源预算 | JSON，如 `{"vram_mb": 8192}`；链路级字段，不属于任何模块 |
| meta_json | 扩展字段 | JSON，如场景描述；链路级字段 |
| created_at / updated_at | 时间戳 | 列表按 `updated_at DESC, id DESC` 倒序 |

### 4.3 当前数据快照

- 行数：**0**；AUTO_INCREMENT=10（历史测试已清理，计数不回退）

## 5. 表：`pipeline_steps`（链路步骤）

### 5.1 建表语句（实测）

```sql
CREATE TABLE `pipeline_steps` (
  `id` int NOT NULL AUTO_INCREMENT,
  `pipeline_id` int NOT NULL,
  `position` int NOT NULL,
  `preset_id` int NOT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_pipeline_position` (`pipeline_id`,`position`),
  KEY `idx_preset` (`preset_id`),
  CONSTRAINT `fk_step_pipeline` FOREIGN KEY (`pipeline_id`) REFERENCES `pipelines` (`id`) ON DELETE CASCADE,
  CONSTRAINT `fk_step_preset` FOREIGN KEY (`preset_id`) REFERENCES `presets` (`id`) ON DELETE RESTRICT
) ENGINE=InnoDB AUTO_INCREMENT=18 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
```

### 5.2 字段说明（通俗版）

| 字段 | 含义 | 说明 |
|---|---|---|
| id | 自增主键 | — |
| pipeline_id | 所属链路 | 外键 → `pipelines.id` |
| position | 步骤顺序 | 同链路内 0..n-1 唯一；`load` 按它排序还原链路 |
| preset_id | 模块配置引用 | 外键 → `presets.id`，且该行 `kind` 必须为 `module`；"角色"（yolo/vlm…）从 `presets.module_id` 反查，不另存 |

### 5.3 引用完整性

- 删链路 → 步骤级联删除（`ON DELETE CASCADE`）。
- 删被引用的模块 preset → **拒绝**：`ON DELETE RESTRICT` 兜底 + `delete_preset` 先查引用、
  报错带引用它的链路名。

### 5.4 当前数据快照

- 行数：**0**；AUTO_INCREMENT=18（历史测试已清理，计数不回退）

## 6. 行为约定（presets 读写语义）

- **命名即身份**：同 kind + name 再次保存 = 覆盖（UPDATE），返回 `created=false`；
  新名字则 INSERT，返回 `created=true`。前端提示"已保存 / 同名配置已覆盖"。
- **module 参数读写走模块参数表**：save 事务内 upsert `presets`（params_json 置空）+ 对应
  `preset_params_<module_id>`（参数按类型强转后写入）；load/list 从参数表组装回 `{param: 值}`
  对象返回。pipeline 类型不受影响（仍 JSON）。
- **列表**：按 `updated_at DESC, id DESC` 倒序；module 行参数由参数表组装，pipeline 行解析
  `params_json`。
- **取用**：按 id 返回完整记录；id 不存在时报错。
- **删除**：幂等，删不存在的 id 不报错；module 行的参数表行由外键级联清理。
- **容错**：未注册模块的 module 行参数按空对象 `{}` 处理；`params_json` 无法解析时按 `{}`
  处理，不抛异常。

## 7. 与 HTTP 接口的对应

| 接口 | 方法 | 调用的 db 函数 | 说明 |
|---|---|---|---|
| /api/presets?kind=module | GET | list_presets | 列出某类配置 |
| /api/presets/save | POST | save_preset | 保存/覆盖（body: kind/name/module_id/params） |
| /api/presets/load | POST | load_preset | 按 id 取回 |
| /api/presets/delete | POST | delete_preset | 按 id 删除 |
| /api/pipelines | GET | list_pipelines | 链路列表（含每步 preset 引用与模块名） |
| /api/pipelines/save | POST | save_pipeline | 保存/覆盖（body: name/steps:[preset_id,…]/streams/budget/meta） |
| /api/pipelines/load | POST | load_pipeline | 按 id 取回完整链路（stages 带参数） |
| /api/pipelines/delete | POST | delete_pipeline | 按 id 删除（级联删步骤） |
| /api/db/tables | GET | table_snapshots | 各表只读快照（presets / 各模块参数表 / pipelines / steps），DB 不可用时 `{ok:false}` |

## 8. 扩展注意事项

- 服务器启动时 `db.configure_modules(...)` 注册各模块参数 schema（来源 server.py 的 PARAMS），
  随后 `init_db()` 幂等建表（`CREATE TABLE IF NOT EXISTS`）+ 为每个已注册模块补建/补列参数表
  + 迁移旧 JSON 数据，表缺失会自动补建。
- 模块参数清单变化（server.py PARAMS 加参数）→ 重启后自动 `ALTER TABLE ... ADD COLUMN` 补列；
  删参数不删列（保守）。
- 若要新增表（如保存测试记录、校准结果），沿用同一访问层模式：
  在 `db.py` 增加对应函数，惰性连接与 MYSQL_* 环境变量覆盖无需改动。
