# UMVP 数据库结构说明

> 本文档描述 web_lab 命名配置暂存（presets）所用 MySQL 库的当前结构，
> 与代码同步更新。数据依据：2026-09-20 对重建后运行实例的实测。

## 1. 概览

- **用途**：web_lab 前端"命名配置暂存/取用"的后端存储，把各模块/链路的命名配置
  （preset）存下来，供以后按名字取回复用。
- **数据库名**：`umvp`（默认，可用 `MYSQL_DB` 覆盖）
- **表数量**：3 张主表（`presets` / `pipelines` / `pipeline_steps`）+ 每模块一张参数表
  `preset_params_<module_id>`（8 个产品模块 → 8 张参数表，见 §3.5）
- **ID 规则（2026-09-20 起）**：presets.id / pipelines.id 为"前缀+4 位序号"的
  业务编号（如 `YOLO0001`、`PIPE0001`），新建时按前缀自动递增；前缀表见 §3.1。
- **播种（seed）**：服务器启动时 `_seed_pipeline()` 幂等写入**唯一保留链路**
  （警用无人机链路 PIPE0001）+ 8 条模块 preset（每模块恰一份），见 §3.6
- **引擎/字符集**：InnoDB / utf8mb4 / utf8mb4_unicode_ci
- **访问层**：`web_lab/db.py`（惰性连接 + 全局锁串行化，pymysql），
  HTTP 接口在 `web_lab/server.py`

## 2. 运行实例信息

| 项 | 值 | 覆盖方式 |
|---|---|---|
| 主机 | 127.0.0.1 | `MYSQL_HOST` |
| 端口 | 3307 | `MYSQL_PORT` |
| 用户 | umvp | `MYSQL_USER` |
| 密码 | 123 | `MYSQL_PASSWORD` |
| 数据库 | umvp | `MYSQL_DB` |

实例自含于项目内（免 sudo 启动）：

```bash
mysqld --datadir=项目/.mysql/data --socket=项目/.mysql/mysql.sock \
       --port=3307 --bind-address=127.0.0.1 --log-error=项目/.mysql/mysql.log
```

MySQL 不可用时不影响 web_lab 启动：`--no-db` 可显式禁用，presets 接口统一返回"未启用"。

### 2.1 运维命令（状态 / 开启 / 关闭）

```bash
# ---- 查看状态 ----
mysqladmin --socket=项目/.mysql/mysql.sock -u root ping   # 输出 mysqld is alive 即正常
ss -ltn | grep 3307                                       # 端口是否在监听
mysql --socket=项目/.mysql/mysql.sock -u umvp -p123 umvp \
  -e "SHOW TABLES; SELECT id,kind,name FROM presets;"     # 看库内容（应用账号）
tail -n 30 项目/.mysql/mysql.log                          # 排错看错误日志

# ---- 开启 ----
# 方式一：起 web_lab 时自动拉起（run.sh 检测 socket 不存在则自行启动，无需手动管）
./web_lab/run.sh --port 8001
# 方式二：单独手动启动
mysqld --datadir=项目/.mysql/data --socket=项目/.mysql/mysql.sock \
       --port=3307 --bind-address=127.0.0.1 \
       --log-error=项目/.mysql/mysql.log --daemonize

# ---- 关闭 ----
# umvp 应用账号没有 SHUTDOWN 权限，必须用 root 走 socket
mysqladmin --socket=项目/.mysql/mysql.sock -u root shutdown
```

注意两点：

- `--log-error` 必须指到项目内（默认 `/var/log/mysql/` 普通用户写不了，会导致启动失败）。
- 关库不影响 web_lab 启动，只是 presets 界面显示"数据库不可用"；`./web_lab/run.sh --no-db` 可显式禁用数据库。
数据库故障只影响暂存功能，不影响测试/校准等其它能力。

## 3. 表：`presets`（命名配置）

### 3.1 建表语句 + 业务 ID 规则

```sql
CREATE TABLE `presets` (
  `id` varchar(24) COLLATE utf8mb4_unicode_ci NOT NULL,
  `kind` enum('module','pipeline') COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT 'module',
  `name` varchar(64) COLLATE utf8mb4_unicode_ci NOT NULL,
  `module_id` varchar(32) COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT '',
  `params_json` text COLLATE utf8mb4_unicode_ci NOT NULL,
  `created_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_kind_name` (`kind`,`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
```

**业务 ID = 模块前缀 + 4 位序号**，由 `db.py` 在新建时按前缀自动递增分配
（查同前缀最大序号 +1，锁内执行）；再存一条 YOLO 配置即得 `YOLO0002`。
前缀登记在 `db.py` `_ID_PREFIXES`：

| 模块 | 前缀 | 模块 | 前缀 |
|---|---|---|---|
| frame_manager | FM | face_store | FSTO |
| yolo | YOLO | extract_faces | EXTF |
| vlm | VLM | （链路：pipelines / kind='pipeline'） | PIPE |
| alarm | AL | | |
| face_detect | FDET | | |
| face_embed | FEMB | | |

**旧 schema 自动迁移**：`init_db()` 检测到 `presets.id` 仍是旧的自增整数
（2026-09-20 之前的库）时，自动 DROP 全部配置相关表并按新 schema 重建——
表内均为播种/测试数据，服务器启动随即重新播种唯一保留链路，换机/升级零手工操作。

### 3.2 字段说明（通俗版）

| 字段 | 含义 | 说明 |
|---|---|---|
| id | 业务 ID | 形如 `YOLO0001`；`load`/`delete` 按它定位；定向更新（保 id 改参数）也按它 |
| kind | 配置类型 | `module`＝单模块配置；`pipeline`＝链路 JSON 快照（当前产品只用 pipelines 结构化链路，此类型保留兼容） |
| name | 配置名 | 同 kind 下必须唯一；重复保存＝覆盖旧配置，不新建 |
| module_id | 模块标识 | 仅 `module` 类型用（如 `yolo`、`frame_manager`） |
| params_json | 配置内容 | 仅 `pipeline` 类型用；`module` 类型迁移后恒为空串，参数改存模块参数表（§3.5） |
| created_at / updated_at | 时间戳 | 列表按 `updated_at DESC, id DESC` 倒序（最近用的在前） |

### 3.3 索引

| 索引 | 列 | 类型 | 作用 |
|---|---|---|---|
| PRIMARY | id | 主键 | 按 id 精确取用/删除 |
| uk_kind_name | kind, name | 唯一索引 | 保证"同 kind 下名字唯一"，并支撑同名覆盖判断 |

### 3.4 当前数据快照（2026-09-20 重建后实测）

- 行数：**8**，全部 `kind='module'`，每模块恰一份：

| id | name | module_id |
|---|---|---|
| FM0001 | 警用无人机·帧管理 | frame_manager |
| YOLO0001 | 警用无人机·YOLO识别 | yolo |
| VLM0001 | 警用无人机·VLM研判 | vlm |
| AL0001 | 警用无人机·告警策略 | alarm |
| FDET0001 | 人脸检测·默认 | face_detect |
| FEMB0001 | 人脸嵌入·默认 | face_embed |
| FSTO0001 | 向量底库·默认 | face_store |
| EXTF0001 | 原分辨率提取·默认 | extract_faces |

- 无 `kind='pipeline'` 行：链路统一存 `pipelines` + `pipeline_steps`（§4/§5），
  不再用 JSON 快照双轨表示。
- 历史清理：2026-09-20 整理时由旧整数 schema DROP 重建完成——此前累积的
  29 条 module 行（含 11 条历史「·默认」、4 条"(配置扩展)"）与 4 条
  pipeline JSON 快照全部随重建清除。

### 3.5 每模块一张参数表（`preset_params_<module_id>`，列式存储）

模块参数**不整份塞进 `params_json`**，而是按模块拆成一张参数表，每参数一列、类型化存储。
设计细节见 `doc/存储设计.md`，这里只记结构事实。

- 表名：`preset_params_<module_id>`，主键 `preset_id`（VARCHAR(24)）引用
  `presets.id`，外键级联删除（删 presets 行时参数自动清理）。
- 列：每个参数一列，类型由 server.py 参数类型映射（int→INT / float→DOUBLE /
  bool→TINYINT(1) / select→VARCHAR(64) / file→VARCHAR(255) / str→VARCHAR(255) /
  text→TEXT）。
- 当前注册 8 张（仅产品模块，server.py 启动时按 `hidden` 过滤后注册）：alarm /
  extract_faces / face_detect / face_embed / face_store / frame_manager / vlm / yolo。
  web 端隐藏运行器（chain / face_monitor / frame_yolo，另有无参数的 pipeline_run）
  是运行入口而非产品模块，不注册 schema、不建参数表、参数 preset 不落库
  （保存时明确报"schema 未注册"）。
- 表与列由 `init_db()` 按 `configure_modules()` 注册的 schema 自动管理：加参数自动
  补列；参数下线/标记 test_only 后其历史列自动删除（`_prune_stale_columns`，列随
  schema 双向收敛——2026-09-20 起，原"删参数不删列（保守）"约定作废）。已下线/
  不落库模块（见 db.py `_PRUNED_MODULES`：frame_scheduler / compose / utest /
  chain / face_monitor / frame_yolo）在启动时幂等清理（删表删行）。
- **test_only 测试参数不落库**（2026-09-20 起）：测试图片/演示回填字段/事件脚本等
  仅存在于 web 模块测试页（PARAMS 里标 `"test_only": true`，前端单独分区展示），
  不注册 schema、不建列；链路设计器阶段表单也不显示。

当前行数：8 张参数表各 **1** 行（对应 §3.4 的 8 条 preset）。

### 3.6 唯一保留链路播种（`_seed_pipeline`）

服务器启动时（`main()` 里 `init_db()` 之后）自动调用 `web_lab/server.py`
的 `_seed_pipeline()`，播种内容（幂等：同名已存在则**跳过**，尊重用户在
web 端的编辑）：

- **8 条模块 preset**（`_SEED_STAGES` 4 条 + `_SEED_STANDALONE` 4 条，
  见 §3.4 清单）：警用链路四阶段参数为 2026-08-24 实调值
  （imgsz=1280 / conf=0.25 等，见 doc/modules/ 各分册）；
- **1 条链路行**：`PIPE0001` 警用无人机链路，4 个步骤按序引用
  FM0001→YOLO0001→VLM0001→AL0001（§4.4）。

播种来源已收敛到这一处（原 server.py 双链路种子、tests/police_uav_config.py、
tests/face_dedup_config.py 均已移除）。

## 4. 表：`pipelines`（链路拼装）

链路 = 一组**有序**模块步骤，每步引用一个已入库的模块 preset（`presets.id`，`kind='module'`）。
"只记 id + 顺序"之外的补充决策（链路级字段、角色从 preset 反查、引用完整性）见
`doc/存储设计.md`。

### 4.1 建表语句（实测）

```sql
CREATE TABLE `pipelines` (
  `id` varchar(24) COLLATE utf8mb4_unicode_ci NOT NULL,
  `name` varchar(64) COLLATE utf8mb4_unicode_ci NOT NULL,
  `streams` int NOT NULL DEFAULT '1',
  `budget_json` text COLLATE utf8mb4_unicode_ci NOT NULL,
  `meta_json` text COLLATE utf8mb4_unicode_ci NOT NULL,
  `created_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
```

### 4.2 字段说明（通俗版）

| 字段 | 含义 | 说明 |
|---|---|---|
| id | 业务 ID | `PIPE` 前缀自动递增（PIPE0001→PIPE0002…）；save/load/delete 按它定位 |
| name | 链路名 | 必须唯一；重复保存＝覆盖旧链路（id 不变、步骤重建），不新建 |
| streams | 路数 | 多路外推，默认 1 |
| budget_json | 资源预算 | JSON，如 `{"vram_mb": 8192}`；链路级字段，不属于任何模块 |
| meta_json | 扩展字段 | JSON，如场景描述；链路级字段 |
| created_at / updated_at | 时间戳 | 列表按 `updated_at DESC, id DESC` 倒序 |

### 4.3 当前数据快照（2026-09-20 实测）

- 行数：**1**——`PIPE0001` 警用无人机链路（streams=1，meta 带 description），
  步骤引用见 §3.6。

## 5. 表：`pipeline_steps`（链路步骤）

### 5.1 建表语句（实测）

```sql
CREATE TABLE `pipeline_steps` (
  `id` int NOT NULL AUTO_INCREMENT,
  `pipeline_id` varchar(24) COLLATE utf8mb4_unicode_ci NOT NULL,
  `position` int NOT NULL,
  `preset_id` varchar(24) COLLATE utf8mb4_unicode_ci NOT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_pipeline_position` (`pipeline_id`,`position`),
  KEY `idx_preset` (`preset_id`),
  CONSTRAINT `fk_step_pipeline` FOREIGN KEY (`pipeline_id`) REFERENCES `pipelines` (`id`) ON DELETE CASCADE,
  CONSTRAINT `fk_step_preset` FOREIGN KEY (`preset_id`) REFERENCES `presets` (`id`) ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
```

（`id` 为内部自增主键，非业务编号；业务定位用 `(pipeline_id, position)`。）

### 5.2 字段说明（通俗版）

| 字段 | 含义 | 说明 |
|---|---|---|
| id | 自增主键 | 内部行号 |
| pipeline_id | 所属链路 | 外键 → `pipelines.id`（如 PIPE0001） |
| position | 步骤顺序 | 同链路内 0..n-1 唯一；`load` 按它排序还原链路 |
| preset_id | 模块配置引用 | 外键 → `presets.id`（如 YOLO0001），且该行 `kind` 必须为 `module`；"角色"（yolo/vlm…）从 `presets.module_id` 反查，不另存 |

### 5.3 引用完整性

- 删链路 → 步骤级联删除（`ON DELETE CASCADE`）。
- 删被引用的模块 preset → **拒绝**：`ON DELETE RESTRICT` 兜底 + `delete_preset` 先查引用、
  报错带引用它的链路名。

### 5.4 当前数据快照（2026-09-20 实测）

- 行数：**4**——PIPE0001 的步骤 0..3 依次引用 FM0001 / YOLO0001 / VLM0001 / AL0001。

## 6. 行为约定（presets 读写语义）

- **命名即身份**：同 kind + name 再次保存 = 覆盖（UPDATE），返回 `created=false`；
  新名字则 INSERT（自动分配前缀 ID），返回 `created=true`。
- **定向更新**：给定 `preset_id` 时按 id 覆盖参数（id 稳定、链路引用不漂移），
  名称留空沿用原名——链路设计器"单模块保存"即走此路径。
- **module 参数读写走模块参数表**：save 事务内 upsert `presets`（params_json 置空）+ 对应
  `preset_params_<module_id>`（参数按类型强转后写入）；load/list 从参数表组装回 `{param: 值}`
  对象返回。pipeline 类型仍 JSON。
- **列表**：按 `updated_at DESC, id DESC` 倒序。
- **取用**：按 id 返回完整记录；id 不存在时报错。
- **删除**：幂等，删不存在的 id 不报错；module 行的参数表行由外键级联清理。
- **容错**：未注册模块的 module 行参数按空对象 `{}` 处理；`params_json` 无法解析时按 `{}`
  处理，不抛异常。

## 7. 与 HTTP 接口的对应

| 接口 | 方法 | 调用的 db 函数 | 说明 |
|---|---|---|---|
| /api/presets?kind=module | GET | list_presets | 列出某类配置 |
| /api/presets/save | POST | save_preset | 保存/覆盖（body: kind/name/module_id/params，可选 preset_id 定向更新） |
| /api/presets/load | POST | load_preset | 按 id 取回 |
| /api/presets/delete | POST | delete_preset | 按 id 删除 |
| /api/pipelines | GET | list_pipelines | 链路列表（含每步 preset 引用与模块名） |
| /api/pipelines/save | POST | save_pipeline | 保存/覆盖（body: name/steps:["YOLO0001",…]/streams/budget/meta） |
| /api/pipelines/load | POST | load_pipeline | 按 id 取回完整链路（stages 带参数） |
| /api/pipelines/delete | POST | delete_pipeline | 按 id 删除（级联删步骤） |
| /api/db/tables | GET | table_snapshots | 各表只读快照（presets / 各模块参数表 / pipelines / steps），DB 不可用时 `{ok:false}` |

## 8. 扩展注意事项

- 服务器启动时 `db.configure_modules(...)` 注册各模块参数 schema（来源 server.py 的 PARAMS，
  hidden 运行器与 test_only 测试参数被过滤），随后 `init_db()` 幂等建表（含旧整数 schema
  自动 DROP 重建，见 §3.1）+ 为每个已注册模块补建/补列/清理废弃列参数表 + 迁移旧 JSON
  数据，表缺失会自动补建。
- 模块参数清单变化（server.py PARAMS 加参数）→ 重启后自动 `ALTER TABLE ... ADD COLUMN` 补列；
  参数删除或标记 test_only → 重启后自动 `DROP COLUMN`（数据可再生，一致性优先）。
- 新增模块：server.py MODULES 注册后，在 db.py `_ID_PREFIXES` 登记前缀（未登记时按
  module_id 前 4 字符大写兜底）。
- 若要新增表（如保存测试记录、校准结果），沿用同一访问层模式：
  在 `db.py` 增加对应函数，惰性连接与 MYSQL_* 环境变量覆盖无需改动。
