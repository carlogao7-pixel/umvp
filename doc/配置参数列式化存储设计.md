# 配置参数列式化存储设计（每模块一张参数表）

> 技术设计文档。把 `presets` 表里 `kind='module'` 配置的 `params_json` 展开为**每模块一张
> 参数表**（类型化列），替代"整份 JSON 塞一列"的存储方式。与"数据库可视化页"
> （web 端数据浏览）配套：二维表结构让"按模块看配置"直观、且日后新增模块不影响旧表。

## 1. 背景与目标

现状（`doc/数据库结构.md` §3）：所有模块的命名配置统一存 `presets` 一张表，参数整体
JSON 序列化进 `params_json`。问题：

- 可视化页想把参数展示成二维表时，不同模块字段各不相同，宽表（一个模块一行、所有模块
  字段当列）会随着模块数量**无限积累列**，且大量单元格为空；
- 参数以字符串 JSON 存储，无法按列类型约束/查询。

**方案 B（用户选定）：每个模块各自维护一张参数表**，参数展开为类型化列；`presets` 表
降级为"注册表"（只保留归属信息），`pipeline` 类型配置不受影响（仍是整份 JSON 快照）。

## 2. 设计决策

### 2.1 presets 保留为注册表，不删

- `presets` 仍承担：`id`（被 `pipeline_steps` 外键引用）、`kind`、`name`（命名即身份，
  同名覆盖）、`module_id`、`created_at/updated_at`（列表倒序）。
- `kind='module'` 行的 `params_json` **迁移后置空**，参数改存模块参数表；
- `kind='pipeline'` 行不变，仍整体存 `params_json`（链路 spec 结构不固定，不适合列式）。

### 2.2 每模块一张参数表

表名：`preset_params_<module_id>`（如 `preset_params_yolo`）。建表语句示例：

```sql
CREATE TABLE IF NOT EXISTS preset_params_yolo (
  preset_id INT NOT NULL PRIMARY KEY,          -- 引用 presets.id（module 行）
  conf DOUBLE NULL,
  iou DOUBLE NULL,
  imgsz INT NULL,
  roi TINYINT(1) NULL,
  model_path VARCHAR(255) NULL,
  ...                                           -- 每参数一列，类型由参数类型映射
  CONSTRAINT fk_pp_yolo FOREIGN KEY (preset_id) REFERENCES presets(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

要点：

- 主键 = `preset_id`（一列一行，配置与参数 1:1）；外键级联删除——`delete_preset` 删注册表
  行时参数自动清理，无需额外代码。
- 模块参数清单来自 `web_lab/server.py` 的 `PARAMS`（前端表单的"参数即表单"来源），
  **参数定义仍只有这一处**，DB 列只是它的物化。

### 2.3 类型映射（server.py 参数类型 → 列类型）

| 参数 type | 列类型 | 说明 |
|---|---|---|
| int | `INT` | 数值输入 |
| float | `DOUBLE` | 阈值、比例等 |
| bool | `TINYINT(1)` | 复选框，存 0/1 |
| select | `VARCHAR(64)` | 下拉选项（值短） |
| file | `VARCHAR(255)` | 文件/路径选择 |
| str | `VARCHAR(255)` | 短文本 |
| text | `TEXT` | 脚本、时间线、提示词等长文本 |

### 2.4 列变更（模块日后加参数）

- **加参数**：`init_db()` 对每个已注册模块校验表存在性与列存在性（`SHOW COLUMNS`），
  缺列时 `ALTER TABLE ... ADD COLUMN` 自动补列——**改 schema 不用手工 DDL**。
- **删参数**：不删列（保守，避免丢数据），只是读写不再涉及该列。
- 表与列名均来自 `MODULES` 白名单（`[a-z0-9_]{1,32}`），防注入。

### 2.5 读写路径

| 操作 | module 类型 | pipeline 类型 |
|---|---|---|
| save | 事务内：upsert `presets`（params_json=''）+ upsert `preset_params_<mid>`（参数按类型强转） | 照旧 `params_json` |
| load | 注册表行 + 模块参数表行 → 组装 `{param: 值}` | 照旧 JSON 解析 |
| list | 注册表全行 + 按 module_id 分组批量查参数表 | 照旧 |
| delete | 删注册表行，参数表级联删 | 照旧 |

`load_pipeline`（链路还原）的 stages 参数同样改为从模块参数表取回（按 module_id 分组
批量查），保持 `{module_id, params}` 输出不变。

### 2.6 旧数据迁移

`init_db()` 里做一次幂等迁移：`kind='module'` 且 `params_json` 非空的行 → 按 `module_id`
拆列写入对应参数表 → 清空 `params_json`。已清空的跳过（幂等）。

### 2.7 与可视化页的关系

新增 `GET /api/db/tables` 返回各表快照（二维数组 `columns` + `rows`），前端"数据浏览"
tab 渲染：

- presets 注册表（id/kind/name/module_id/时间戳）；
- 每个模块一张参数表（配置名 + 参数列 + 更新时间）——**正是列式化的直接收益**；
- pipelines / pipeline_steps 表。

只读展示，不做在线编辑/删除（改数据走现有"命名暂存"界面，保留引用完整性保护）。

## 3. 访问层（web_lab/db.py 变更）

| 函数 | 变更 |
|---|---|
| `configure_modules(schemas)` | **新增**：server.py 启动时注册 `{module_id: {参数名: 参数type}}`，db 据此建表/强转 |
| `init_db()` | 建三张主表后，对每个已注册模块 ensure 参数表（含补列），再跑幂等迁移 |
| `save_preset(...)` | module 分支改事务拆列写；pipeline 分支不变 |
| `load_preset(...)` / `list_presets(...)` | module 分支改从参数表组装；pipeline 不变 |
| `load_pipeline(...)` | stages 参数改从模块参数表取回 |
| `delete_preset(...)` | 不变（参数表靠级联清理） |
| `table_snapshots()` | **新增**：返回各表 `{columns, rows}` 快照 |

`module_id` 需白名单校验（`[a-z0-9_]{1,32}`），防表名注入。

## 4. HTTP API（web_lab/server.py 变更）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/db/tables` | GET | `{ok, presets, modules:[{module_id, name, columns, rows}], pipelines, steps}`；DB 不可用/未启用时 `{ok:false}`（沿用容错模式） |

`main()` 启动时在 `init_db()` 前调用 `db.configure_modules(...)`，把 `MODULES` 的参数
类型映射喂给 db。

## 5. 前端（web_lab/index.html 变更）

- 顶部 tab 增加"数据浏览"（`data-view="db"`）；
- 渲染：表总览（表名 + 行数）、presets 注册表、每模块参数表（caption=模块名）、
  pipelines/steps 表；
- 数据源：`fetch("/api/db/tables")`；DB 不可用时显示"数据库不可用"。

## 6. 边界与后续

- `params_json` 列保留（pipeline 类型 + 兼容），module 行置空。
- 模块参数清单改动（server.py PARAMS）即 DB 列改动来源：加参数自动补列、删参数不删列。
- 未注册模块（`_MODULE_SCHEMAS` 中没有）的 module 行按空参数 `{}` 处理，不报错。

## 7. 验证方法（断言式回归）

启动自含 MySQL（`doc/数据库结构.md` §2.1）后跑回归，全部通过即算验证闭环：

1. `configure_modules` 后 `init_db()` 幂等：重复调用不报错；各模块参数表存在。
2. module preset save → load：参数按类型往返一致（int/float/bool/str/text 各验证）。
3. 同名再次 save（不同参数）→ 同一 id，参数被覆盖。
4. 列表按 `updated_at DESC` 倒序；params 与库中一致。
5. 未注册模块的 module 行 load → `params={}`（容错）。
6. `table_snapshots()` 返回的三表 + 各模块表列/行与库中一致。
7. pipeline 类型 save/load 不受影响（仍 JSON）。
8. 删除 module preset → 参数表行级联删除。
9. 旧 JSON 数据（default1）迁移：params_json 置空、参数落入对应模块表。
10. curl 实测 `/api/db/tables`；测试数据清理，库回到干净状态。
