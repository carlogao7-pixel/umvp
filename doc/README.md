## 一、业务架构（这个系统做什么）

**UMVP（统一模块化视觉分析管道）**：对视频/图片做智能视觉分析——按节奏抽帧 →
小模型（YOLO）识别目标 →（可选）大模型（VLM）语义研判 → 统一输出处理
（告警 / 记录 / 素材留存）。**链路由模块自定义拼接**，不预设固定模式。

### 1.1 三条保留链路（开箱即用）

| 链路 | 业务目的 | 流程 | 详见 |
|---|---|---|---|
| PIPE0001 警用无人机链路 | 无人机画面警情监测 | 帧管理 → YOLO 识人车 → **标注** → VLM 研判警情 → 输出处理（告警） | `modules/警用无人机链路.md` |
| PIPE0002 车牌识别链路 | 车辆车牌识别与存证 | 帧管理 → YOLO 识车 → **目标裁剪(裁车)** → 车牌识别（裁车牌→识别→坐标还原→原分辨率提取车牌小图）→ 输出处理 | `modules/车牌识别.md` §8 |
| PIPE0003 人脸截取链路 | 原分辨率人脸截取归档 | 帧管理 → YOLO 识人 → **目标裁剪(裁人)** → 人脸检测（检脸+原图出脸）（无嵌入/检索/告警，截取落盘即目的） | `modules/目标裁剪.md` §5 |

### 1.2 平台通用能力

- **链路设计器**：在 web 测试台把模块排成阶段、逐阶段调参、存成新链路并运行
- **资源估算（P1）**：每模块/整链路的显存/内存/耗时估算（静态公式 + 实测指纹两层），
  支持多路外推与预算反推
- **可视化测试台**：单模块测试页 + 链路批量运行 + **实时播放叠加**（任务进行时同步播放
  视频，检测/车牌框实时叠在画面上；HEVC 等浏览器不支持的编码按需自动转 H.264 后播放）
- **AI 组装（P4）**：总装/组装工两个 agent + 链路拼接知识库（skill），自然语言需求 →
  方案（含资源估算）→ 自动测试

### 1.3 统一输出抽象（业务语义）

多帧视觉分析的输出判定 = **识别到对象 → 驻留时间足够 → 识别对象特征（车牌号/颜色/
VLM 描述与词表分类等）→ 置信度足够 → 去重冷却 → 输出**。任何链路的输出都走同一条
「七道闸漏斗」（含自定义规则条件 DSL，如仪表盘读数越限），详见 `modules/输出处理.md`。

## 二、技术结构（怎么实现的）

**技术栈**：Python 3.10（conda 环境 `ai`）＋ ultralytics(YOLO) ＋ insightface(SCRFD/ArcFace)
＋ HyperLPR3(车牌) ＋ onnxruntime/cv2/numpy ＋ stdlib http.server（web 测试台零框架）＋
本地 MySQL（自含 3307，presets/pipelines 暂存）。代码与权重自包含于项目目录，整目录拷贝即可移植。

### 2.1 分层结构

```
web_lab/（可视化测试台）
 ├ index.html 模块测试/链路设计器/数据浏览   ├ db.py MySQL 配置暂存（惰性连接）
 ├ test.html 链路测试台（批量运行 + SSE 同步播放叠加）
 └ server.py 全部 API + 链路运行器（_chain_from_spec 装配 → Pipeline 驱动）
     │
 umvp/pipe/（管道核心）
 ├ composer.py  FrameManager 帧管理(取帧节奏+背压) / YOLODetector 小模型识别 /
 │              VLMAnalyzer 大模型研判 / OutputPolicy 输出处理七道闸(原告警) / Pipeline 装配器
 ├ cropper.py   通用裁剪工具 Cropper（按框裁图可缩放/坐标还原/原分辨率提取，纯 cv2+numpy）
 ├ target_crop.py  目标裁剪模块（按上游检测框裁子图，输出分辨率可配；车牌/人脸/VLM 链共用）
 ├ annotate.py  标注模块（在帧上画检测框，供 VLM 看"原图+画框"；纯绘制）
 └ crop_restore.py  extract_faces 兼容编排（已拆为「目标裁剪+人脸检测」两模块）
     │
 专用模块
 ├ umvp/plate_recog/   PlateRecognizer(HyperLPR3) + PlateStage(链路阶段) + extract_plates
 ├ umvp/face_detect/   FaceDetector(SCRFD+5点对齐) + FaceStage(检脸+原图出脸) + providers.py
 ├ umvp/face_embed/    FaceEmbedder(ArcFace 512d) + FaceStore(numpy 线性检索底库)
 └ umvp/resources.py   ResourceEstimator 资源估算（静态公式+实测指纹）
     │
 模型/数据：models/(YOLO 权重池) face_models/(buffalo_l) plate_models/(hyperlpr3)
           out/fingerprints.json(实测指纹)  本地 MySQL(presets/pipelines)
```

### 2.2 关键机制速览

| 机制 | 一句话 | 权威文档 |
|---|---|---|
| 帧管理门控 | frame_skip/墙钟/帧数三式取帧 + EMA 背压自适应放宽 | `modules/帧管理.md` |
| IntervalGate 统一节流 | yolo→vlm 报送 / yolo→车牌车辆框共用同一段间隔门控（key=类别/track） | `modules/YOLO识别.md` §2 |
| 输出七道闸 + 规则 DSL | 驻留/词表/置信度/规则/滑窗/去重冷却；`features.reading >= 80` 式自定义条件 | `modules/输出处理.md` |
| 目标裁剪 + 原分辨率提取 | 按 YOLO 框裁子图（分辨率可配）→识别模块裁二次目标→坐标还原→从原图直接裁出小图（零缩放） | `modules/目标裁剪.md`、`modules/车牌识别.md` |
| track 去重 | 车牌按 track_id 只识别一次（冷却可重试）；输出按车牌号只报一次 | `modules/车牌识别.md` §5 |
| 实时播放叠加 | SSE 逐分析帧推框数值，浏览器播视频 + canvas 叠加，播放节流保同步 | `实时播放叠加设计.md` |
| 参数入库 | 每模块一张参数表，schema 双向收敛（加参数补列/删参数删列），test_only 不落库 | `数据库结构.md` §3.5 |
| 部署台账 | 影响部署的改动只追加记录于 `DEPLOYMENT.md` | 根目录 `DEPLOYMENT.md` |
